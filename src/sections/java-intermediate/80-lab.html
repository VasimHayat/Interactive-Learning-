Put it together

Hands-on lab: the pricing and reporting pipeline

Six steps that turn the Fundamentals warehouse into a reporting system, each exercising something from this module. Write each step before opening its solution — the solutions are short, and reading one you have not attempted teaches almost nothing. The whole thing fits in one file; a real project would split the records, the discounts and the catalogue into their own.

Starter
mkdir order-lab && cd order-lab
# one file, OrderLab.java, grown step by step
javac OrderLab.java && java OrderLab

JDK 21 is required: record patterns in switch (step 2) were finalised in 21. Prices stay in cents as long — never double for money.

Step 1 — the domain as records §8

Define a Category enum and three records: Product(sku, name, category, priceInCents), OrderLine(product, qty) with a subtotal(), and Order(id, placed, lines) with a subtotal() that sums its lines. Validate in compact constructors: no blank SKU, no negative price, no non-positive quantity, no empty order. Make sure an Order cannot be changed by whoever still holds the list that was passed in.

Solution — step 1
enum Category { FASTENER, STRUCTURAL, MECHANICAL }

record Product(String sku, String name, Category category, long priceInCents) {
    Product {
        if (sku == null || sku.isBlank()) throw new IllegalArgumentException("sku required");
        Objects.requireNonNull(name, "name");
        Objects.requireNonNull(category, "category");
        if (priceInCents < 0) throw new IllegalArgumentException("price must not be negative: " + priceInCents);
    }
}

record OrderLine(Product product, int qty) {
    OrderLine {
        Objects.requireNonNull(product, "product");
        if (qty <= 0) throw new IllegalArgumentException("qty must be positive: " + qty);
    }
    long subtotal() { return product.priceInCents() * qty; }
}

record Order(String id, LocalDate placed, List lines) {
    Order {
        Objects.requireNonNull(id, "id");
        Objects.requireNonNull(placed, "placed");
        lines = List.copyOf(lines);                 // the record keeps its own immutable copy
        if (lines.isEmpty()) throw new IllegalArgumentException("order " + id + " has no lines");
    }
    long subtotal() { return lines.stream().mapToLong(OrderLine::subtotal).sum(); }
}

A compact constructor runs before the fields are assigned, so reassigning the parameter lines is how a record normalises its input. List.copyOf gives an immutable, null-rejecting copy — without it, the caller's ArrayList is still reachable and a record that looks immutable is not. equals, hashCode and toString come free and are component-wise, which step 3 relies on when products become map keys.

Step 2 — a sealed discount family §9

Model three discount kinds as a sealed interface Discount with record implementations: PercentOff(percent), FixedOff(cents) and BuyNGetOne(sku, n) ("buy n, get one free" for a single SKU). Write static long discountFor(Discount d, Order order) as a switch expression using record patterns, with no default branch. A fixed discount must never exceed the order's subtotal.

Solution — step 2
sealed interface Discount permits PercentOff, FixedOff, BuyNGetOne {}
record PercentOff(int percent) implements Discount {
    PercentOff { if (percent < 0 || percent > 100) throw new IllegalArgumentException("percent out of range: " + percent); }
}
record FixedOff(long cents) implements Discount {}
record BuyNGetOne(String sku, int n) implements Discount {}

static long discountFor(Discount d, Order order) {
    return switch (d) {
        case PercentOff(int pct)           -> order.subtotal() * pct / 100;
        case FixedOff(long cents)          -> Math.min(cents, order.subtotal());
        case BuyNGetOne(String sku, int n) -> order.lines().stream()
                .filter(l -> l.product().sku().equals(sku))
                .mapToLong(l -> (long) (l.qty() / (n + 1)) * l.product().priceInCents())
                .sum();
    };
}

Because the interface is sealed, the compiler knows the three cases are all the cases and accepts the switch without a default. That is the point: add a fourth discount next quarter and this method stops compiling until it handles it, instead of silently returning zero. A default would have thrown that guarantee away. The record patterns pull the components straight out — no accessor calls, no casts.

Step 3 — the report §5, §6

Given a List<Order>, produce three things with streams and collectors: revenue by Category as a TreeMap; the top three products by revenue as "SKU=cents" strings, ties broken by SKU; and a partition of order ids by whether the order's subtotal exceeds 10,000 cents. Every result must come out in a deterministic order.

Solution — step 3
Map byCategory = orders.stream()
        .flatMap(o -> o.lines().stream())
        .collect(Collectors.groupingBy(l -> l.product().category(), TreeMap::new,
                                       Collectors.summingLong(OrderLine::subtotal)));

Map bySku = orders.stream()
        .flatMap(o -> o.lines().stream())
        .collect(Collectors.groupingBy(l -> l.product().sku(), Collectors.summingLong(OrderLine::subtotal)));
List top3 = bySku.entrySet().stream()
        .sorted(Map.Entry.comparingByValue().reversed().thenComparing(Map.Entry.comparingByKey()))
        .limit(3)
        .map(e -> e.getKey() + "=" + e.getValue())
        .toList();

Map> bigOrders = orders.stream()
        .collect(Collectors.partitioningBy(o -> o.subtotal() > 10_000,
                                           Collectors.mapping(Order::id, Collectors.toList())));

flatMap turns a stream of orders into a stream of lines, which is the grain the first two reports need. The three-argument groupingBy chooses the map type; a TreeMap keyed by an enum iterates in declaration order, so the category report is stable. The top-three query groups into a plain HashMap — order there is irrelevant because the next line sorts — and the explicit type witness on comparingByValue is needed because reversed() breaks the inference chain. partitioningBy always produces both keys, so a report never has to guess whether true is present.

Step 4 — lookups that cannot NPE §7

Write a Catalogue with void add(Product) and Optional<Product> findBySku(String). Then, without calling get() or isPresent(), obtain the price of CAM-9 (throwing IllegalStateException if absent) and the name of NOPE-0 with a fallback string.

Solution — step 4
static final class Catalogue {
    private final Map bySku = new HashMap<>();
    void add(Product p) { bySku.put(p.sku(), p); }
    Optional findBySku(String sku) { return Optional.ofNullable(bySku.get(sku)); }
}

long camPrice = catalogue.findBySku("CAM-9")
        .map(Product::priceInCents)
        .orElseThrow(() -> new IllegalStateException("CAM-9 not in catalogue"));
String unknown = catalogue.findBySku("NOPE-0").map(Product::name).orElse("(unknown sku)");

Optional.ofNullable is the bridge from a Map.get that returns null to an API that says so in its type. map carries the absence through, so the chain reads as the happy path and the fallback is stated once at the end. The exception supplier is a lambda so the message string is only built when it is needed; orElse is fine for a constant string but would be orElseGet if the fallback were expensive.

Step 5 — a composed ranking §10

Rank the orders by subtotal, highest first, and for equal subtotals by the date placed, earliest first. Produce "id(subtotal)" strings. Build the Comparator from the static factories, not a hand-written compare.

Solution — step 5
List ranked = orders.stream()
        .sorted(Comparator.comparingLong(Order::subtotal).reversed().thenComparing(Order::placed))
        .map(o -> o.id() + "(" + o.subtotal() + ")")
        .toList();

comparingLong avoids boxing every subtotal; reversed() flips only the key before it, so the tiebreak that follows still runs ascending. LocalDate is Comparable, which is what lets thenComparing take the accessor directly. sorted is a stateful operation — it must see every order before it can emit the first — which is fine for a list of orders and worth knowing about for a stream of a million lines.

Step 6 — a time window §12

List the ids of orders placed in the seven days up to and including a reference date. Take the reference date as a parameter — LocalDate.of(2026, 10, 15) in main — rather than calling LocalDate.now(), so the method is testable and this page's output is reproducible.

Solution — step 6
LocalDate asOf = LocalDate.of(2026, 10, 15);
LocalDate from = asOf.minusDays(7);
List recent = orders.stream()
        .filter(o -> !o.placed().isBefore(from))
        .map(Order::id)
        .toList();

!isBefore(from) is "on or after", the inclusive bound a window usually needs; isAfter(from) would silently drop orders placed exactly seven days ago. The reference date is a plain parameter here; in a service it would come from an injected Clock, which is the same idea with a type. Either way, "today" is an input, not something the method goes and fetches.

The finished thing

All six steps assembled. This program is compiled and executed during the build of this page, so the output below is what it really prints.

import java.time.LocalDate;
import java.util.Comparator;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.Objects;
import java.util.Optional;
import java.util.TreeMap;
import java.util.stream.Collectors;

public class OrderLab {

    enum Category { FASTENER, STRUCTURAL, MECHANICAL }

    // -- step 1: records with validating compact constructors -----------------
    record Product(String sku, String name, Category category, long priceInCents) {
        Product {
            if (sku == null || sku.isBlank()) throw new IllegalArgumentException("sku required");
            Objects.requireNonNull(name, "name");
            Objects.requireNonNull(category, "category");
            if (priceInCents < 0) throw new IllegalArgumentException("price must not be negative: " + priceInCents);
        }
    }

    record OrderLine(Product product, int qty) {
        OrderLine {
            Objects.requireNonNull(product, "product");
            if (qty <= 0) throw new IllegalArgumentException("qty must be positive: " + qty);
        }
        long subtotal() { return product.priceInCents() * qty; }
    }

    record Order(String id, LocalDate placed, List lines) {
        Order {
            Objects.requireNonNull(id, "id");
            Objects.requireNonNull(placed, "placed");
            lines = List.copyOf(lines);                       // immutable, null-hostile, ours
            if (lines.isEmpty()) throw new IllegalArgumentException("order " + id + " has no lines");
        }
        long subtotal() { return lines.stream().mapToLong(OrderLine::subtotal).sum(); }
    }

    // -- step 2: a sealed family consumed by an exhaustive switch -------------
    sealed interface Discount permits PercentOff, FixedOff, BuyNGetOne {}
    record PercentOff(int percent) implements Discount {
        PercentOff { if (percent < 0 || percent > 100) throw new IllegalArgumentException("percent out of range: " + percent); }
    }
    record FixedOff(long cents) implements Discount {}
    record BuyNGetOne(String sku, int n) implements Discount {}

    static long discountFor(Discount d, Order order) {
        return switch (d) {                                   // no default: the compiler checks coverage
            case PercentOff(int pct)           -> order.subtotal() * pct / 100;
            case FixedOff(long cents)          -> Math.min(cents, order.subtotal());
            case BuyNGetOne(String sku, int n) -> order.lines().stream()
                    .filter(l -> l.product().sku().equals(sku))
                    .mapToLong(l -> (long) (l.qty() / (n + 1)) * l.product().priceInCents())
                    .sum();
        };
    }

    // -- step 4: an Optional-returning lookup ---------------------------------
    static final class Catalogue {
        private final Map bySku = new HashMap<>();
        void add(Product p) { bySku.put(p.sku(), p); }
        Optional findBySku(String sku) { return Optional.ofNullable(bySku.get(sku)); }
    }

    public static void main(String[] args) {
        Product bolt   = new Product("BOLT-7", "M8 bolt",      Category.FASTENER,   80);
        Product nut    = new Product("NUT-3",  "M8 nut",       Category.FASTENER,   25);
        Product girder = new Product("GIRD-1", "Steel girder", Category.STRUCTURAL, 120_000);
        Product cam    = new Product("CAM-9",  "Cam follower", Category.MECHANICAL, 1_450);

        Catalogue catalogue = new Catalogue();
        for (Product p : List.of(bolt, nut, girder, cam)) catalogue.add(p);

        List orders = List.of(
            new Order("A-100", LocalDate.of(2026, 10, 1),  List.of(new OrderLine(bolt, 40), new OrderLine(nut, 40))),
            new Order("A-101", LocalDate.of(2026, 10, 9),  List.of(new OrderLine(girder, 1))),
            new Order("A-102", LocalDate.of(2026, 10, 12), List.of(new OrderLine(cam, 6), new OrderLine(bolt, 10))),
            new Order("A-103", LocalDate.of(2026, 10, 14), List.of(new OrderLine(cam, 2))));

        // step 2 in action
        Order a100 = orders.get(0);
        System.out.println("A-100 subtotal        = " + a100.subtotal());
        for (Discount d : List.of(new PercentOff(10), new FixedOff(5_000), new BuyNGetOne("BOLT-7", 3))) {
            System.out.printf("  %-27s -> %d off%n", d, discountFor(d, a100));
        }

        // -- step 3: the report -------------------------------------------------
        Map byCategory = orders.stream()
                .flatMap(o -> o.lines().stream())
                .collect(Collectors.groupingBy(l -> l.product().category(), TreeMap::new,
                                               Collectors.summingLong(OrderLine::subtotal)));
        System.out.println("revenue by category   = " + byCategory);

        Map bySku = orders.stream()
                .flatMap(o -> o.lines().stream())
                .collect(Collectors.groupingBy(l -> l.product().sku(), Collectors.summingLong(OrderLine::subtotal)));
        List top3 = bySku.entrySet().stream()
                .sorted(Map.Entry.comparingByValue().reversed().thenComparing(Map.Entry.comparingByKey()))
                .limit(3)
                .map(e -> e.getKey() + "=" + e.getValue())
                .toList();
        System.out.println("top 3 products        = " + top3);

        Map> bigOrders = orders.stream()
                .collect(Collectors.partitioningBy(o -> o.subtotal() > 10_000,
                                                   Collectors.mapping(Order::id, Collectors.toList())));
        System.out.println("over 10,000 cents     = " + bigOrders);

        // -- step 4: Optional without get() -------------------------------------
        long camPrice = catalogue.findBySku("CAM-9")
                .map(Product::priceInCents)
                .orElseThrow(() -> new IllegalStateException("CAM-9 not in catalogue"));
        String unknown = catalogue.findBySku("NOPE-0").map(Product::name).orElse("(unknown sku)");
        System.out.println("CAM-9 price           = " + camPrice + ", NOPE-0 -> " + unknown);

        // -- step 5: ranking with a composed Comparator -------------------------
        List ranked = orders.stream()
                .sorted(Comparator.comparingLong(Order::subtotal).reversed().thenComparing(Order::placed))
                .map(o -> o.id() + "(" + o.subtotal() + ")")
                .toList();
        System.out.println("ranked by total       = " + ranked);

        // -- step 6: a time window against a fixed reference date ---------------
        LocalDate asOf = LocalDate.of(2026, 10, 15);
        LocalDate from = asOf.minusDays(7);
        List recent = orders.stream()
                .filter(o -> !o.placed().isBefore(from))
                .map(Order::id)
                .toList();
        System.out.println("placed since " + from + " = " + recent);
    }
}

Two details in the output are worth a second look. The TreeMap lists STRUCTURAL before MECHANICAL — an enum's natural order is its declaration order, not alphabetical, which is exactly what a report usually wants and occasionally surprises. And the three discount lines are the record toString implementations, generated from the component names; a hand-written class would have needed three methods to print as clearly.

Extensions worth attempting
  • Add a fourth discount, FreeShippingOver(long threshold), to the sealed interface and do nothing else. Read the compiler error carefully — it is telling you every switch that now needs a case. Then add a Discount that is itself a record of two discounts applied in sequence; what does the pattern look like?
  • Load the orders from a CSV file with Files.lines (§13) instead of constructing them in main. Decide what a malformed line should do to the import: skip it, stop, or collect the failures with partitioningBy and report them at the end.
  • Replace the Catalogue's HashMap with a map keyed by Product itself, then change a product's price by creating a new Product record. Explain, before running it, why the old entry is still there — and why that is the correct behaviour for a value type.
