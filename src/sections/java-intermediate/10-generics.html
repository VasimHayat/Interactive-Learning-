Section 1

Generics in depth

Fundamentals left generics at the point where you can declare a List<Product> and get a Product back without a cast. That is the consumer's view. This section is the designer's view: how to write a method or class that works for a whole family of types, and why the rules that make that safe produce some of the strangest-looking signatures in the JDK.

Everything follows from one decision made in 2004: generic type arguments exist only at compile time. The compiler checks them, then erases them, and the bytecode that runs contains plain List, plain Object, and a cast wherever you read an element out. Every limitation in this section — no new T(), no List<int>, no instanceof List<String> — is a direct consequence of that.

Invariance: why a List<Perishable> is not a List<Product>

A Perishable is a Product. It is natural to assume a List<Perishable> is therefore a List<Product>, and the compiler says no. Here is why it must:

List dairy = new ArrayList<>();
List products = dairy;              // if this were allowed…
products.add(new Product("GIRD-1", 120_000)); // …a girder would land in the dairy list
Perishable p = dairy.get(0);                 // and this would throw ClassCastException

Generic types are invariant: List<A> and List<B> are unrelated no matter how A and B relate. Arrays, designed a decade earlier, went the other way — Perishable[] is a Product[] — and pay for it at runtime with ArrayStoreException, which the language designers regarded as a mistake not to repeat. Invariance is safe but inconvenient: a method taking List<Product> cannot accept the dairy list even to read it. Wildcards are the fix.

Wildcards and PECS

A wildcard loosens the type argument in one direction. List<? extends Product> means "a list of some unknown subtype of Product"; List<? super Perishable> means "a list of some unknown supertype of Perishable". Which one you want depends entirely on whether the method reads or writes, and the mnemonic is PECS: Producer Extends, Consumer Super.

import java.util.ArrayList;
import java.util.List;

public class Pecs {

    static class Product {
        final String sku; final int priceInCents;
        Product(String sku, int priceInCents) { this.sku = sku; this.priceInCents = priceInCents; }
        @Override public String toString() { return sku; }
    }
    static class Perishable extends Product {
        final int shelfDays;
        Perishable(String sku, int priceInCents, int shelfDays) { super(sku, priceInCents); this.shelfDays = shelfDays; }
    }

    // PRODUCER: we only READ Products out of `src`, so accept any List of a subtype
    static int totalInCents(List src) {
        int sum = 0;
        for (Product p : src) sum += p.priceInCents;   // reading as Product is always safe
        return sum;
    }

    // CONSUMER: we only WRITE Perishables into `dst`, so accept any List of a supertype
    static void restockPerishables(List dst) {
        dst.add(new Perishable("MILK-1", 120, 7));      // writing a Perishable is always safe
        dst.add(new Perishable("EGGS-6", 240, 21));
    }

    // BOTH: reads and writes, so the type must be exact — no wildcard
    static void swapFirstTwo(List list) {
        Product first = list.get(0);
        list.set(0, list.get(1));
        list.set(1, first);
    }

    public static void main(String[] args) {
        List dairy = new ArrayList<>();
        restockPerishables(dairy);                      // List is a List
        System.out.println("dairy         = " + dairy);

        List catalogue = new ArrayList<>();
        catalogue.add(new Product("BOLT-7", 80));
        catalogue.add(new Product("GIRD-1", 120_000));
        restockPerishables(catalogue);                  // List is ALSO a List
        System.out.println("catalogue     = " + catalogue);

        System.out.println("total(dairy)  = " + totalInCents(dairy));       // List as a producer
        System.out.println("total(catal.) = " + totalInCents(catalogue));   // List as a producer
