What you need installed

A JDK 21 or newer. This is not negotiable in the way it was for Fundamentals: records (16), sealed types (17), pattern matching for switch and record patterns (21) are all used as ordinary language here, and an older compiler rejects the examples outright. No IDE is required.

java -version    # expect: openjdk version "21.x" or newer
javac -version   # must match; a mismatched pair causes "class file has wrong version"

If you see UnsupportedClassVersionError when running, your java is older than your javac. Check PATH and JAVA_HOME point at the same installation.

If you skipped Fundamentals

Four ideas carry most of the weight here. If any of these sentences is not obviously true to you, read the Fundamentals section first — it is a twenty-minute detour that saves an hour of confusion.

  • The equals/hashCode contract. Two objects that are equals must return the same hashCode, or every hash-based collection silently misfiles them. Records (§8) exist largely so you stop writing this by hand; HashMap internals (§11) show what goes wrong when the hash changes after insertion.
  • Erasure. List<String> and List<Integer> are the same class at runtime. §1 starts from that fact and derives everything generics can and cannot do.
  • Dynamic dispatch versus static resolution. The JVM picks an override from the runtime class; the compiler picks an overload from the declared types. Lambdas (§4) and default methods (§3) each sit on one side of that line.
  • Try-with-resources. A resource acquired in the header is closed in reverse order, always. A Stream from Files.lines (§13) is such a resource, and forgetting that leaks a file handle.
