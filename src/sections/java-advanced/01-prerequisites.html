What you need installed

A JDK 21 or newer — virtual threads (§7) and the Thread.ofPlatform() builder are final only from 21. Every diagnostic tool this module uses ships inside the JDK: jcmd, jstack, jfr, jconsole and javap live next to javac in its bin directory. No IDE, no profiler licence, nothing to download.

java -version       # expect: openjdk version "21.x" or newer
jcmd -l             # lists the JVMs you can attach to; an empty list is fine for now
jfr --version       # the Flight Recorder command-line tool (§13)

A machine with at least two cores makes the races in §1 reproducible. On a single core they are rarer, not absent — which is the whole point of §2.

Three habits to unlearn

Everything you wrote in the first two modules ran on one thread, and one thread lets you get away with assumptions that are simply false once there are two. Each of these is a bug you will write unless you consciously stop:

  • "count++ is one operation." It is three — load, add, store — and another thread can run between any two of them. §1 shows the increment vanish; §4 shows the one-instruction replacement.
  • "If I wrote it, the other thread can read it." Not unless something orders the write before the read. Without that, the reader is allowed to see the old value forever. §2 names the rules that create the ordering, and there are only a handful.
  • "One thread per task." A platform thread costs a megabyte of stack and a kernel object; ten thousand of them do not fit. §5 pools them, §7 replaces them with something a thousand times cheaper, and both come with new failure modes.
