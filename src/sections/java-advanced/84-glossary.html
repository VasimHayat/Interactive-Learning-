Reference

Glossary

Thirty terms, each linked back to the section that introduces it. The same entries drive the flashcard deck below — one list, two ways to use it.

Flashcards

ABA problem
A compare-and-swap sees the expected value A and succeeds, not knowing the slot went A → B → A in between. Harmless for counters; dangerous when identity matters, which is what AtomicStampedReference is for. §4
Atomicity
An operation that other threads see either entirely done or not at all. count++ is not atomic: it is load, add, store, and another thread can fall into the gaps. §1
Automatic module
A jar without module-info.class placed on the module path. It gets a name from Automatic-Module-Name or its file name, exports every package and reads every module — the bridge for libraries that have not modularised. §12
Carrier thread
A platform thread in the virtual-thread scheduler's ForkJoinPool on which a virtual thread is mounted to run. When the virtual thread blocks it unmounts and the carrier picks up another. §7
Class loader delegation
Before defining a class itself, a loader asks its parent — app → platform → bootstrap. It is why java.lang.String cannot be replaced from the class path, and why class identity is the pair (loader, name). §10
Compare-and-swap
One CPU instruction: "if this location still holds X, store Y and report success". The primitive under every atomic and lock-free structure; a failure means retry, never block. §4
Completion stage
One step of a CompletableFuture pipeline: a function that runs when the previous stage completes, on the completing thread (non-async) or on an executor (*Async). A failed stage skips value stages until a recovery stage. §6
Data race
A write and a conflicting access to the same variable from two threads with no happens-before edge between them. The JMM then permits stale, reordered or torn values; the program is incorrect even if it appears to work. §2
Deadlock
Two or more threads each holding a lock the other needs, forever. Requires mutual exclusion, hold-and-wait, no preemption and a circular wait; cured by a global lock order or tryLock with a timeout. §3
Deoptimization
The JIT throwing away compiled code when an assumption it made stops holding — a new subclass breaks an inlined monomorphic call, an untaken branch is taken — and falling back to the interpreter until it recompiles. §13
Escape analysis
C2 proving that an object never leaves the compiled method, so it can be replaced by its fields in registers (scalar replacement) and never allocated at all — the reason short-lived objects are often free. §13
G1 region
G1 divides the heap into equal regions (1–32 MB) and assigns each a role — eden, survivor, old, humongous — dynamically. A collection evacuates the regions with the most garbage first, which is the "garbage first" in the name. §8
Gadget chain
A sequence of classes already on the class path whose readObject methods, invoked in order by deserializing a crafted stream, end in arbitrary code execution. Why untrusted Java serialization is treated as remote code execution. §14
Generational hypothesis
Most objects die young. Collectors exploit it by collecting the young generation often and by copying the few survivors, so the cost tracks live data rather than garbage. §8
Happens-before
The JMM's partial order. If A happens-before B, B sees A's effects. The edges: program order, monitor unlock → lock, volatile write → read, start, join, and transitivity; everything in java.util.concurrent is built to provide them. §2
Initialization trigger
The first active use that runs a class's static initializers: new, a static method call, a non-constant static field access, Class.forName, or initializing a subclass. Reading a compile-time constant is not one. §10
Inlining
The JIT copying a callee's body into the caller, removing the call and enabling every other optimisation. Limited by bytecode size (35 cold, 325 hot by default) and by megamorphic call sites. §13
Livelock
Threads that keep running but make no progress — two tryLock loops that both back off and retry in step. Cured with randomised back-off or a bound on retries. §3
Load barrier
A few instructions ZGC runs on every reference load that check the pointer's colour bits and, if the object has moved, fix the reference up. The mechanism that lets ZGC relocate objects while the application runs. §8
Metaspace
Native memory holding class metadata, unbounded by default. It grows with every class loader that cannot be collected, which is how hot-redeploy and plugin systems leak until OutOfMemoryError: Metaspace. §9
Monitor
The lock every object carries for synchronized: one owner, an entry set of threads blocked trying to enter, and a wait set of threads parked in wait() that must re-acquire it after notify. Reentrant. §3
Pinning
A virtual thread that cannot unmount from its carrier while blocked — in JDK 21, inside a synchronized block or a native frame. Pinned carriers are the usual reason virtual threads fail to scale; JEP 491 fixes the monitor case in 24. §7
Poison pill
A sentinel object placed on a BlockingQueue to tell a consumer to stop — one per consumer — so shutdown needs no flag polling and no interrupt. §4
Reachability
An object is live if a chain of references leads to it from a GC root — a thread stack, a static field, a JNI handle. Collectors reclaim everything else; a "leak" in Java is an object that is reachable but no longer wanted. §8
Reentrancy
A thread that holds a lock may acquire it again without blocking; the lock counts the depth. Both synchronized and ReentrantLock are reentrant, which is what lets one synchronized method call another on the same object. §3
Rejection policy
What a ThreadPoolExecutor does with a task when its queue is full and it is at maximumPoolSize: throw (AbortPolicy, the default), run it on the submitting thread (CallerRunsPolicy, back-pressure), drop it, or drop the oldest. §5
Safe publication
Making an object visible to other threads through a happens-before edge — a volatile field, a lock, a concurrent collection, a thread start — so they see its fully constructed state rather than a half-built one. Immutable objects with final fields are safe through any route. §2
Stop-the-world
A GC phase during which every application thread is halted at a safepoint so the collector can see a consistent object graph. All of Serial and Parallel, the evacuation pauses of G1, and only the brief phase boundaries of ZGC. §8
Strong encapsulation
The module system's rule that a package is accessible only if exported, and open to deep reflection only if opened. Enforced for the JDK's own internals since Java 16; --add-opens is the per-package escape hatch. §12
Tiered compilation
HotSpot's pipeline from the interpreter (tier 0) through C1 with profiling (tiers 1–3) to C2's optimised code (tier 4), driven by invocation and loop counters, with deoptimization back down when a speculation fails. §13
