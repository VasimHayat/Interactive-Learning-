How to use this module

Work through it at your own pace. Your section checkmarks, quiz answers, flashcard marks and notes are saved in this browser under a key scoped to this file, so closing the tab loses nothing and the earlier modules cannot overwrite it. Nothing is sent anywhere — this page makes no network requests at all. Press ? at any time for the keyboard shortcuts, and use Reset progress in the sidebar to start over.

Every code sample in this module was compiled and executed against a real JDK 21 as part of the build. If an Expected output block appears under a program, that text is what the program actually printed. This module adds one twist: much of it is about threads, and two runs of a threaded program rarely interleave the same way. So the verified programs print facts established after every thread has finished — all joined: true, a sorted list, a count compared with what it should be — never a raw number that depends on which thread won. Where you need to see a race unfold, an animation does it step by step and carries the Simulated badge. Java cannot run in a browser, and this module does not pretend otherwise.

The warehouse under load

Fundamentals built an InventoryService; Intermediate turned it into a pricing and reporting pipeline. Both were single-threaded on purpose. This module takes the same service and asks it to survive what production actually looks like:

  • Many pickers at once. Dozens of threads reserve BOLT-7 and NUT-3 simultaneously, and stock must never go negative or be double-counted (§1–§4).
  • A background re-pricing job that rewrites prices while orders are being totalled, without a report ever seeing half-updated state (§2, §3, §6).
  • Thousands of waiting requests served by a small pool, then by virtual threads, and the difference measured rather than asserted (§5, §7, §13).
  • A JVM that stays responsive while it does all of that: how the collector reclaims the garbage those orders produce, how the heap is sized, and how to read what the runtime tells you when it does not (§8, §9).
  • The machinery underneath — class loading, reflection, modules and serialization — which every framework you will meet is built from (§10–§12, §14).
