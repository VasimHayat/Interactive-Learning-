Cheat sheet

Everything worth having in front of you while a service is misbehaving. This section is laid out to print cleanly — controls and navigation are hidden, and tables are kept whole across page breaks. Each block names the section it condenses.

count++ is load, add, store — three operations with a gap another thread can fall into. Happens-before edges §2

The happens-before rules of the Java memory model
RuleEdge
Program ordereach action in a thread → every later action in that thread
Monitor lockunlock of M → every later lock of the same M
Volatilewrite to v → every later read of v (and everything before the write becomes visible: piggybacking)
Thread startt.start() → every action in t
Thread terminationevery action in t → t.join() returning / isAlive() false
Interruptiont.interrupt() → t detecting it
Final fieldsconstructor end → any thread that sees the reference sees the final fields
TransitivityA → B and B → C gives A → C
java.util.concurrentevery submit → the task; task completion → Future.get; countDown → await returning; put → the matching take

A data race is a write and a conflicting access with no happens-before edge between them. volatile gives visibility and ordering, not atomicity: volatile int i; i++ still loses updates. Immutable objects published through any edge are safe; the holder idiom and volatile double-checked locking are the two correct lazy-init shapes.

Deadlock needs all four: mutual exclusion, hold-and-wait, no preemption, circular wait. Break the last one with a global lock order, or the second with tryLock and back-off:

void transfer(Account a, Account b, int qty) {
    Account first  = a.id().compareTo(b.id()) < 0 ? a : b;   // global order, never identityHashCode
    Account second = first == a ? b : a;
    synchronized (first) { synchronized (second) { move(a, b, qty); } }
}

boolean transferWithTimeout(Account a, Account b, int qty) throws InterruptedException {
    while (true) {
        if (a.lock().tryLock(10, MILLISECONDS)) {
            try {
                if (b.lock().tryLock(10, MILLISECONDS)) {
                    try { move(a, b, qty); return true; } finally { b.lock().unlock(); }
                }
            } finally { a.lock().unlock(); }
        }
        Thread.sleep(ThreadLocalRandom.current().nextInt(5));   // back off, or livelock
    }
}

Lock on a private final Object lock, never on this, a String, or a boxed value. Always loop on the condition around wait(); prefer notifyAll.

ConcurrentHashMap: no null keys or values; per-bin locking on writes, lock-free reads; compute* is atomic per key only; iterators are weakly consistent; size() is an estimate under concurrent writes. CAS is one CPU instruction that succeeds only if the slot still holds the expected value — a retry loop, not a block. The ABA problem: the value went A → B → A and the CAS cannot tell; use AtomicStampedReference when identity matters.

ThreadPoolExecutor growth rule: below core → new thread; at core → queue first; only when the queue is full → grow to max; then the RejectedExecutionHandler (AbortPolicy default, CallerRunsPolicy for back-pressure). Size: CPU-bound ≈ cores; I/O-bound ≈ cores × (1 + wait/compute). Always shutdown() then awaitTermination, or use the Java 19+ close() in try-with-resources; non-daemon pool threads keep the JVM alive. A task's exception goes into its Future — if nobody calls get(), nobody sees it.

Generational hypothesis: most objects die young, so eden is collected by copying survivors — cost is proportional to live objects, not garbage. Reference strength: strong → soft (cleared under memory pressure) → weak (cleared at the next GC) → phantom (post-mortem, via a ReferenceQueue). finalize() is gone; use Cleaner, and never capture this in the cleaning action. Four OOMs: Java heap space, Metaspace, GC overhead limit exceeded, unable to create native thread.

Class loading §10

Class initialization triggers and the loader hierarchy
Initializes the classDoes not
new; a static method call; a non-constant static field read or write; Class.forName(name); initializing a subclass; a reflective call; the main class at start-upreading a compile-time constant (static final primitive/String literal — it is inlined); loadClass; Class.forName(name, false, loader); an array type Prices[]; a .class literal; a subclass's static member that is inherited from a superclass (initializes only the declaring class)

Phases: loading (bytes → Class) → linking (verify, prepare defaults, resolve lazily) → initialization (<clinit>: superclass first, then textual order, once, under a lock). Loaders: bootstrap (null, java.base) ← platform ← app; parent delegation asks the parent first, so java.lang.String cannot be replaced. Identity is (loader, name): the same bytes in two loaders are two classes. ClassNotFoundException is "never found" (checked, from forName/loadClass); NoClassDefFoundError is "found at compile time, missing or broken now" — Could not initialize class means an earlier ExceptionInInitializerError.

Annotations are metadata: @Retention(RUNTIME) or reflection cannot see them (the default is CLASS); @Target limits placement; @Repeatable needs a container; @Inherited applies to class annotations only. Module directives §12

Readability (requires) is necessary but not sufficient; accessibility also needs the package exported and the member public. Class-path code lives in the unnamed module, reads every module, and can reflect into any opens but not into java.base internals: the fix is --add-opens java.base/java.lang=ALL-UNNAMED, the cure is to stop needing it. A jar on the module path without module-info becomes an automatic module named from Automatic-Module-Name or its file name. Split packages are forbidden. jdeps finds your dependencies; jlink builds a runtime with only the modules you use.

JIT tiers and JMH pitfalls §13

HotSpot compilation tiers
TierCodeEntered after
0interpreter, collecting countsfirst call
1–3C1 (3 = full profiling)~200 invocations or hot loops (OSR)
4C2, with inlining, escape analysis, scalar replacement~5,000 invocations / ~15,000 back-edges
deoptback to the interpreteran uncommon trap: a new subclass broke a monomorphic inline, a null appeared, a branch never taken was taken

Inlining limits (defaults): MaxInlineSize 35 bytecodes for cold calls, FreqInlineSize 325 for hot ones; megamorphic call sites (three or more receiver types) are not inlined. JMH pitfalls: dead-code elimination (return the value or sink it into a Blackhole), constant folding (read inputs from @State fields, not literals), no warm-up / no forks (@Warmup, @Fork(1+)), GC noise and CPU frequency. A result faster than a cycle is a bug in the benchmark, not a miracle. First three things to check for a slow service: the GC log, a thread dump under load, the hot methods from JFR.
