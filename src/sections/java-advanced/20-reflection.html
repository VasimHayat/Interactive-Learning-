Section 11

Reflection, annotations and method handles

Everything so far has been code that knows, at compile time, which class it is talking to. Reflection is the escape hatch: a program that inspects classes it has never heard of, reads their fields, calls their methods, and constructs them, all by name and all at runtime. Every framework you will use is built on it — dependency injection finds constructors, serializers find fields, test runners find methods, validators find annotations. You will rarely write reflective code in application logic, and you will constantly debug code that does.

The price is real: the compiler cannot check names or types, the JIT cannot inline through a Method.invoke, arguments are boxed, every call re-checks access, and since JDK 16 the JDK's own internals are closed to it. This section covers the API, its costs, the annotation system it usually serves, and the two modern alternatives — method handles and var handles — that recover most of the speed.

Worked example: inspecting and invoking at runtime

import java.lang.invoke.MethodHandle;
import java.lang.invoke.MethodHandles;
import java.lang.invoke.MethodType;
import java.lang.invoke.VarHandle;
import java.lang.reflect.Field;
import java.lang.reflect.InaccessibleObjectException;
import java.lang.reflect.Method;
import java.lang.reflect.Modifier;
import java.lang.reflect.Proxy;
import java.lang.reflect.RecordComponent;
import java.util.Arrays;

public class Reflection {

    interface PriceSource {
        int priceInCents(String sku);
        String name();
    }

    record Product(String sku, int priceInCents) { }

    static class Vault {
        private final String secret = "rotate-me";
        private volatile int stock = 10;

        private static final VarHandle STOCK;
        static {
            try {
                STOCK = MethodHandles.lookup().findVarHandle(Vault.class, "stock", int.class);
            } catch (ReflectiveOperationException e) {
                throw new ExceptionInInitializerError(e);
            }
        }
        boolean reserve(int expected, int remaining) { return STOCK.compareAndSet(this, expected, remaining); }
    }

    public static void main(String[] args) throws Throwable {
        System.out.println("-- inspecting a record --");
        Class c = Product.class;
        System.out.println("isRecord         = " + c.isRecord() + ", final = " + Modifier.isFinal(c.getModifiers()));
        System.out.println("components       = " + Arrays.stream(c.getRecordComponents()).map(RecordComponent::getName).sorted().toList());
        System.out.println("declared methods = " + Arrays.stream(c.getDeclaredMethods()).filter(m -> !m.isSynthetic()).map(Method::getName).sorted().toList());

        System.out.println("-- constructing and invoking by name --");
        Product p = c.getDeclaredConstructor(String.class, int.class).newInstance("BOLT-7", 80);
        Method sku = c.getMethod("sku");
        System.out.println("sku()            = " + sku.invoke(p) + "  (public: " + Modifier.isPublic(sku.getModifiers()) + ")");

        System.out.println("-- private access: your own class yes, java.base no --");
        Field secret = Vault.class.getDeclaredField("secret");
        secret.setAccessible(true);
        System.out.println("Vault.secret     = " + secret.get(new Vault()));
        try {
            Field value = String.class.getDeclaredField("value");
            value.setAccessible(true);
            System.out.println("opened java.lang.String.value");
        } catch (InaccessibleObjectException e) {
            System.out.println("String.value     : blocked by strong encapsulation");
        }

        System.out.println("-- a dynamic proxy --");
        PriceSource source = (PriceSource) Proxy.newProxyInstance(
                Reflection.class.getClassLoader(), new Class[] { PriceSource.class },
                (self, method, a) -> {
                    System.out.println("  intercepted " + method.getName() + (a == null ? "()" : Arrays.toString(a)));
                    return method.getName().equals("name") ? "proxy" : 80;
                });
        System.out.println("proxy price      = " + source.priceInCents("BOLT-7"));
        System.out.println("proxy name       = " + source.name());

        System.out.println("-- method handles and var handles --");
        MethodHandle price = MethodHandles.lookup()
                .findVirtual(Product.class, "priceInCents", MethodType.methodType(int.class));
        int cents = (int) price.invokeExact(p);
        System.out.println("invokeExact      = " + cents);
        Vault vault = new Vault();
        System.out.println("CAS 10 -> 7      = " + vault.reserve(10, 7));
        System.out.println("CAS 10 -> 3      = " + vault.reserve(10, 3) + "  (stock is now " + vault.stock + ")");
    }
}

Five things happened, and each is a different tool:

  • Class is the entry point. getRecordComponents, getDeclaredMethods, getDeclaredConstructor and Modifier describe the type. The declared variants return what the class itself declares, private included; the plain variants (getMethod) return public members including inherited ones. Note the program sorts every listing — the JDK documents the order as unspecified, and it really does vary between JVM builds.
  • setAccessible(true) is the switch that bypasses access control, and it works on Vault because Vault is in your own module (the unnamed module, here). It fails on String.value with InaccessibleObjectException: java.base does not open java.lang to you. That is strong encapsulation (§12), the JDK 17 change that broke a generation of libraries which had been poking at JDK internals. The escape is --add-opens java.base/java.lang=ALL-UNNAMED on the command line, and it should feel like what it is: a deliberate hole.
  • Proxy fabricates an implementation of an interface at runtime whose every method lands in one InvocationHandler. It is how a mocking library builds a mock, how a remote call looks like a local one, and how a transaction annotation wraps a method. It works only for interfaces; for classes you need a bytecode library (ByteBuddy, which is what Mockito and Hibernate use).
  • A MethodHandle is a typed, direct reference to a method, looked up once and then invoked at near-native speed: no boxing with invokeExact, access checked at lookup time rather than per call, and the JIT can inline through a constant handle. The cast (int) price.invokeExact(p) is not a normal cast — it tells the compiler the exact call-site type, which must match the handle's type to the letter.
  • A VarHandle is the same idea for a field, with atomic operations attached: compareAndSet, getAndAdd, volatile and acquire/release reads and writes. It is the official replacement for sun.misc.Unsafe and for AtomicIntegerFieldUpdater, and it is how the java.util.concurrent classes you met in §4 are implemented. The second CAS fails because the stock is no longer 10 — exactly the lost-update protection §1 wanted.

Annotations: metadata, not behaviour

An annotation does nothing by itself. @Audited on a method changes no bytecode in that method. It is a note attached to the class file that something else reads — the compiler (@Override, @FunctionalInterface), an annotation processor at build time (Lombok, MapStruct, records of configuration), or, most commonly, a framework using reflection at runtime. The retention policy decides how far the note travels.

import java.lang.annotation.ElementType;
import java.lang.annotation.Repeatable;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import java.lang.reflect.Field;
import java.lang.reflect.Method;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class Annotations {

    @Retention(RetentionPolicy.RUNTIME)
    @Target({ ElementType.TYPE, ElementType.METHOD })
    @interface Audited {
        String by();
        int level() default 1;
    }

    @Retention(RetentionPolicy.SOURCE)             // discarded by javac
    @Target(ElementType.METHOD)
    @interface Draft { }

    @Retention(RetentionPolicy.RUNTIME)
    @Target({ ElementType.FIELD, ElementType.RECORD_COMPONENT })
    @interface NotBlank { }

    @Repeatable(Tags.class)
    @Retention(RetentionPolicy.RUNTIME)
    @interface Tag { String value(); }

    @Retention(RetentionPolicy.RUNTIME)
    @interface Tags { Tag[] value(); }

    @Audited(by = "ops", level = 3)
    @Tag("inventory") @Tag("critical")
    static class InventoryService {
        @Audited(by = "finance") void reprice() { }
        @Draft void experimental() { }
        void plain() { }
    }

    record Part(@NotBlank String sku, @NotBlank String name, int qty) { }

    /* A tiny validation framework: the metadata is on the type, the behaviour is here. */
    static List validate(Object target) throws IllegalAccessException {
        List problems = new ArrayList<>();
        Field[] fields = target.getClass().getDeclaredFields();
        Arrays.sort(fields, (a, b) -> a.getName().compareTo(b.getName()));
        for (Field f : fields) {
            if (!f.isAnnotationPresent(NotBlank.class)) continue;
            f.setAccessible(true);
            Object v = f.get(target);
            if (v == null || v.toString().isBlank()) problems.add(f.getName() + " must not be blank");
        }
        return problems;
    }

    public static void main(String[] args) throws Exception {
        System.out.println("-- reading annotation values --");
        Audited onType = InventoryService.class.getAnnotation(Audited.class);
        System.out.println("type: by=" + onType.by() + " level=" + onType.level());

        Method[] methods = InventoryService.class.getDeclaredMethods();
        Arrays.sort(methods, (a, b) -> a.getName().compareTo(b.getName()));
        for (Method m : methods) {
            Audited a = m.getAnnotation(Audited.class);
            System.out.println(m.getName() + "(): audited=" + (a != null ? "by " + a.by() + " level " + a.level() : "no")
                    + ", @Draft visible=" + m.isAnnotationPresent(Draft.class));
        }

        System.out.println("-- repeatable --");
        Tag[] tags = InventoryService.class.getAnnotationsByType(Tag.class);
        System.out.println("tags = " + Arrays.stream(tags).map(Tag::value).sorted().toList()
                + " (container present: " + InventoryService.class.isAnnotationPresent(Tags.class) + ")");

        System.out.println("-- annotations drive a validator --");
        System.out.println("valid   : " + validate(new Part("BOLT-7", "hex bolt", 3)));
        System.out.println("invalid : " + validate(new Part("BOLT-7", "   ", 3)));
    }
}

@Draft is on experimental() in the source and invisible at runtime: RetentionPolicy.SOURCE means javac drops it after compilation (useful for annotation processors and lint tools). CLASS — the default if you write nothing — keeps it in the class file but does not load it, so it is equally invisible to reflection; RUNTIME is the one you want almost every time. The repeatable @Tag shows the mechanism behind the convenience: the compiler wraps the two tags in an implicit @Tags container, and getAnnotationsByType unwraps it. And @NotBlank on a record component was propagated by javac to the generated private field (its @Target includes FIELD), which is what lets the validator find it with getDeclaredFields.

All four correct. Plain reflection is fine when it runs once and clarity matters more than speed. A hot path wants a MethodHandle held in a static final so the JIT can inline it. Atomic field updates are exactly what VarHandle exists for. And getRecordComponents returns components in declaration order — unlike getDeclaredFields, whose order is unspecified — which is why serializers use it.

What it costs, and what replaced it

A reflective call is slower than a direct one for four reasons, and knowing them tells you which alternative fixes which. Lookup: getMethod("sku") scans and copies the method table — cache the Method, never look it up per call. Access checks: each invoke re-verifies that the caller may call; setAccessible(true) skips that. Boxing: arguments travel as Object[] and primitives are boxed both ways. Opacity: the JIT sees a call into Method.invoke, not into your method, so nothing inlines. Method handles address the last two: invokeExact takes primitives as primitives, and a handle in a static final field is a constant the JIT can see through. That is also the machinery under lambdas — a lambda expression compiles to an invokedynamic instruction whose bootstrap method spins a class at first call and links a method handle to it, which is why a lambda is cheaper than the anonymous class it replaced (Intermediate §2).

Reflection gotchas
  • Method.invoke wraps every exception. Whatever the target throws arrives as InvocationTargetException; the real exception is getCause(). Frameworks that forget to unwrap it produce stack traces that blame the framework.
  • Reflection ignores generics (erasure, Intermediate §1). Field.getType() of a List<Product> is List; the type argument is only available through getGenericType() and only because javac kept a Signature attribute for it.
  • Strong encapsulation is on by default since JDK 17. A library that worked on 11 by opening java.base fails on 21 with InaccessibleObjectException. --add-opens is a stop-gap; the right fix is a library version that does not need it.
  • Reflection defeats the tools that make Java safe. Renaming a field breaks a string-based lookup silently; dead-code analysis cannot see reflective uses; ahead-of-time compilation (GraalVM native image) needs an explicit list of everything reflected on. Keep reflection at the edges — serializers, DI, tests — never in domain code.
  • A Proxy cannot wrap a class, only interfaces, and final classes cannot be subclassed by bytecode libraries either. Records are final: a framework that proxies entities cannot proxy a record.

Check yourself

1.You declare @interface Timed { } with no meta-annotations, put it on a method, and at runtime method.isAnnotationPresent(Timed.class) returns false. Why?

C. Without @Retention(RetentionPolicy.RUNTIME) an annotation defaults to CLASS retention — recorded in the .class file for tools, invisible to reflection. It is the single most common annotation mistake.

A is backwards: no @Target means it is allowed anywhere. B is invented — marker annotations are common and fully supported. D describes @Inherited, which widens what is found; it never narrows it.

2.A serialization library worked on JDK 11 and on JDK 21 fails with InaccessibleObjectException: Unable to make field private final byte[] java.lang.String.value accessible. What changed, and what is the correct long-term response?

B. JEP 403 (JDK 17) stopped the JDK from opening its packages to the class path by default. The library was relying on a hole that has now closed. The honest fix is a version of the library that uses supported APIs; --add-opens java.base/java.lang=ALL-UNNAMED keeps you running meanwhile.

A is wrong on the facts — the field exists, which is exactly why the message names it. C is wrong twice: reflection was not removed, and method handles go through the same access checks. D is backwards — code on the class path (the unnamed module) can reflect on itself freely; modules make encapsulation stronger, not weaker.

3.A hot loop calls a method selected from configuration at start-up. Profiling shows Method.invoke at the top. Which changes actually help? Select all that apply.

A and C. Lookup per call is the first thing to remove — it copies the method table every time. Then a constant MethodHandle with invokeExact removes boxing and lets the JIT inline through the call, which a Method.invoke never allows.

B adds a layer: the proxy's handler still has to call Method.invoke underneath, so it is strictly slower. D confuses two unrelated things — retention is about annotations on the method, and nothing about annotations affects inlining.
