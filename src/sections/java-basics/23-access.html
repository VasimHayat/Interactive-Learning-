Section 14

Packages and access modifiers

A package is a namespace and a unit of access control. The declaration must be the first statement in the file, and the directory structure has to match: package com.acme.inventory; lives in com/acme/inventory/. Package names are reverse domain names to keep them globally unique.

Four access levels control who may see a member. The one people get wrong is the one you get by writing nothing at all.

Two things the table cannot show
  • There is no package keyword for access. Omitting a modifier is the declaration — the level is called package-private. Writing nothing is a decision, not a default you have deferred.
  • protected is narrower than it looks. A subclass in another package may access a protected member only through a reference of its own type (or a subtype), not through a bare superclass reference. other.shippingInCents() where other is declared Product will not compile inside Girder, even though Girder inherits it.

Encapsulation in practice

public class Order {
    private final String id;                       // nobody can reassign it
    private final List lines = new ArrayList<>();
    private Status status = Status.DRAFT;

    public Order(String id) {
        this.id = Objects.requireNonNull(id, "id");
    }

    public void addLine(OrderLine line) {          // the ONLY way lines change
        if (status != Status.DRAFT) throw new IllegalStateException("order is " + status);
        lines.add(line);
    }

    public List lines() {
        return List.copyOf(lines);                 // defensive copy, not the field
    }
}

Line 12 is the part people skip. Returning the lines field directly would hand callers a live, mutable reference to internal state — they could add lines to a shipped order and bypass the check in addLine entirely. List.copyOf returns an immutable snapshot, so the invariant survives contact with the outside world. Making the field final only stops reassignment of the reference; it does nothing to stop mutation of what it points at.

Gotchas
  • One public top-level class per file, named after the file. Additional non-public classes in the same file are legal but are usually better off as nested or separate types.
  • Access is per class, not per object. A method of Order can read other.status on a different Order instance — which is how equals works at all.
  • Start private and widen only when forced. Widening later is easy; narrowing a member other people already call is a breaking change.
  • Getters and setters for every field are not encapsulation. A setStatus that skips the state machine is a public field wearing a disguise. Expose operations — ship(), cancel() — not fields.
  • Wildcard imports hide clashes. import java.util.*; plus import java.sql.*; makes Date ambiguous and the file stops compiling. Import explicitly.

Check yourself

1.A field is declared int qty; with no modifier. Which callers can read it?

B. That is package-private. The unit of trust is the package, so any class sitting in the same one has full access — including classes someone else adds to that package later.

A is the most common wrong answer; private must be written explicitly. C is how it works in some other languages, not Java. D describes protected, which is strictly wider — it adds out-of-package subclasses on top of package access.

2.lines is private final, and lines() returns the field directly. A caller does order.lines().clear(). What happens?

C. The getter handed out a live reference to internal state, so the caller is now mutating the order's own list. Every invariant addLine protects is bypassed. Return List.copyOf(lines) — or better, expose no getter at all and add the operation the caller actually needs.

A confuses the field's access with the method's: lines() is public and hands the reference out legitimately. B is the crucial misunderstanding — final prevents reassigning the variable, never mutation of the object it refers to. D invents a defensive copy Java does not make for you.
