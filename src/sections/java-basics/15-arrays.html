Section 6

Arrays

An array is a fixed-length, contiguous block of same-typed slots. It is the only built-in container in the language — ArrayList and friends are ordinary classes built on top of one. Arrays are objects, so an array variable holds a reference, and length is a field rather than a method.

Three properties cause nearly all array bugs: the length is fixed at creation, indices run from 0 to length - 1, and arrays do not override equals or toString.

Indices and bounds

Where the boundary actually is

Worked example

import java.util.Arrays;

public class ArrayBasics {
    public static void main(String[] args) {
        int[] qty = new int[4];
        System.out.println("defaults      = " + Arrays.toString(qty));

        String[] skus = { "BOLT-7", "NUT-3", "CAM-9" };
        System.out.println("length        = " + skus.length);
        System.out.println("last element  = " + skus[skus.length - 1]);

        int[][] weekly = new int[3][];
        weekly[0] = new int[] { 5, 3 };
        weekly[1] = new int[] { 9 };
        weekly[2] = new int[] { 1, 1, 4 };
        System.out.println("jagged        = " + Arrays.deepToString(weekly));

        int[] grown = Arrays.copyOf(qty, 6);
        System.out.println("copyOf(6)     = " + Arrays.toString(grown));

        String[] a = { "BOLT-7" };
        String[] b = { "BOLT-7" };
        System.out.println("a == b        -> " + (a == b));
        System.out.println("a.equals(b)   -> " + a.equals(b));
        System.out.println("Arrays.equals -> " + Arrays.equals(a, b));
    }
}
  
defaults      = [0, 0, 0, 0]
length        = 3
last element  = CAM-9
jagged        = [[5, 3], [9], [1, 1, 4]]
copyOf(6)     = [0, 0, 0, 0, 0, 0]
a == b        -> false
a.equals(b)   -> false
Arrays.equals -> true

Lines 20–22 are the trap. Arrays inherit equals from Object, so it is pure identity comparison — exactly the same as ==. Two arrays with identical contents are never equals to each other. You need Arrays.equals for one dimension or Arrays.deepEquals for nested arrays. The same applies to printing: System.out.println(skus) gives you something like [Ljava.lang.String;@1b6d3586, which is the type descriptor and an identity hash, not the contents.

The off-by-one, in full

This is the single most common array bug. The loop condition uses <= where it needs <:

public class ArrayBounds {
    public static void main(String[] args) {
        String[] skus = { "BOLT-7", "NUT-3", "CAM-9" };
        for (int i = 0; i <= skus.length; i++) {
            System.out.println(i + " -> " + skus[i]);
        }
    }
}
  
0 -> BOLT-7
1 -> NUT-3
2 -> CAM-9
  
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException:
        Index 3 out of bounds for length 3
        at ArrayBounds.main(ArrayBounds.java:5)

Both the printed lines and the exception type above were captured from an actual run during the build. Read the message literally — it names the offending index and the array's length, which together tell you the loop ran exactly one iteration too many.

Prevent it structurally

Use the enhanced for whenever you do not need the index: for (String sku : skus) cannot go out of bounds, because you never write a bound. Reach for the indexed form only when the index is genuinely part of the logic.

Array gotchas
  • length is a field, not a method. array.length but string.length() and list.size(). Three containers, three spellings.
  • An array of objects is an array of nulls. new String[3] gives you three null slots, not three empty strings. Touching one before assigning it throws NullPointerException.
  • Arrays cannot be resized. "Growing" one means allocating a new array and copying, which is what Arrays.copyOf does and what ArrayList does for you automatically.
  • Arrays.asList returns a fixed-size view. Arrays.asList(skus).add("X") throws UnsupportedOperationException, and writes through the list mutate the original array. For an independent, resizable copy use new ArrayList<>(Arrays.asList(skus)).
  • Cloning is shallow. weekly.clone() copies the outer array of references; both copies still share the same inner arrays. Mutating weekly[0][0] is visible through both.

Check yourself

1.A test asserts two arrays are equal and fails, though both print the same values element by element. Which comparison was used, and what should it be?

C. Arrays never override equals, so the inherited Object.equals runs and compares references. Two distinct arrays are never equal that way regardless of contents.

A has it backwards: Arrays.equals works fine for object element types too — deepEquals is only needed for nested arrays. B contradicts the premise that the elements match. D is invented; sorting matters for binarySearch, not equality.

2.What does new int[3] contain, and what does new String[3] contain?

B. Array elements always get the default value for their type: numeric zero for primitives, false for boolean, and null for any reference type.

A forgets that int is a primitive and cannot hold null. C is the common wrong guess — Java never manufactures empty strings for you, which is why iterating a fresh String[] and calling a method on each element throws NullPointerException. D confuses array elements with local variables; locals must be definitely assigned before use, array elements are zero-initialised by the JVM.
