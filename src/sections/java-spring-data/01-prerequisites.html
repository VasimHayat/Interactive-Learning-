Before you begin

Prerequisites

This module assumes JPA & Hibernate, and through it the earlier modules. It does not re-teach mapping: when a section shows an entity, it reads as a reminder, not an introduction. Spring Data is a thin layer, and almost every surprise in it is a JPA fact wearing a Spring stack trace, so the items below are leaned on constantly:

What you need installed

A JDK 21 or newer, plus the Spring Boot jars — 61 of them once the transitive graph is resolved, which is why this module's dependency list is not pinned by hand but resolved by Maven against Spring Boot's bill of materials. If you are working from the course repository, one command does it (it needs a Maven on your PATH, in MAVEN_HOME, or in the Maven Wrapper's cache under ~/.m2/wrapper):

node tools/fetch-deps.mjs java-spring-data     # resolves Spring Boot 4.1.1's graph into build/lib/java-spring-data/
javac -cp "build/lib/java-spring-data/*" -d classes BootAnatomy.java
java  -cp "classes;build/lib/java-spring-data/*" lm.anatomy.BootAnatomy   # : instead of ; on Linux/macOS

In a project of your own, the same stack is three starters under the Spring Boot parent — the parent is what pins every version:

<parent>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-parent</artifactId>
  <version>4.1.1</version>
</parent>
<dependencies>
  <dependency><groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-data-jpa</artifactId></dependency>
  <dependency><groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-validation</artifactId></dependency>
  <dependency><groupId>com.h2database</groupId><artifactId>h2</artifactId><scope>runtime</scope></dependency>
</dependencies>

No versions on the starters: the parent's dependencyManagement supplies them, and that is exactly the mechanism fetch-deps reproduces by importing spring-boot-dependencies as a BOM. Every program in this module names its own package (lm.anatomy, lm.repos, …) because Spring component-scans the package of the application class, and the build compiles all programs into one directory.

Three habits to unlearn

Spring Data removes so much code that it is easy to stop thinking about what the remaining code does. Three habits in particular survive every code review and fail in production:

  • "@Transactional on the method is enough." The annotation does nothing by itself; a proxy around the bean does the work, and a call that does not pass through the proxy — a private method, a method the same object calls on itself — gets no transaction at all. Section 5 proves it with a transaction-name check that prints null.
  • "Lazy loading just works in Spring." It works in a web request because open-in-view keeps a persistence context open from controller to template, which hides every N+1 behind a working page. Switch it off and the same code throws. Section 6 does exactly that.
  • "ddl-auto=update keeps the schema in sync." Spring Boot defaults it to create-drop for an embedded database and none otherwise, and the JPA module already explained why update is a development convenience and never a deployment. Section 12 shows where Flyway slots in.
