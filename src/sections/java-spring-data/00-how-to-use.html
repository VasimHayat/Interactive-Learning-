How to use this module

Work through it at your own pace. Your section checkmarks, quiz answers, flashcard marks and notes are saved in this browser under a key scoped to this file, so closing the tab loses nothing and the earlier modules cannot overwrite it. Nothing is sent anywhere — this page makes no network requests at all. Press ? at any time for the keyboard shortcuts, and use Reset progress in the sidebar to start over.

Every program in this module is a complete Spring Boot application, compiled and executed as part of the build against a pinned stack: Spring Boot 4.1.1, Spring Data JPA 4.1.1, Hibernate ORM 7.4.5 and an in-memory H2 database, on JDK 21 — the versions Spring Boot's own dependency management selects, resolved by Maven when the page was built. As in the JPA module, every line beginning Hibernate: in an Expected output block is a statement that was actually sent to the database, and the prose reads those statements one by one. When a section says a repository method ran two queries, the build counted them. Widgets that animate something — the autoconfiguration order, a save decision, a transaction proxy — carry the Simulated badge.

Why every program looks the same at the bottom

A Spring Boot application normally prints a banner, a dozen INFO lines with timestamps and the process id, and a "Started in 2.31 seconds" line. None of that is repeatable, and the build diffs standard output byte for byte. So every program here sets the same small property map before it starts, and it is worth knowing what each entry does, because you will want most of them in a test suite too:

The deterministic property set used by every program in this module
PropertyWhy it is set
spring.main.web-application-type=noneNo embedded server. The application runs its runners and exits; nothing listens on a port.
spring.main.banner-mode=offNo ASCII-art banner on standard output.
spring.main.log-startup-info=falseNo "Starting BootAnatomy using Java 21 with PID …" lines, which carry the process id and the machine name.
logging.level.root=WARNLogback writes to standard output by default. At WARN the startup chatter is gone; anything that still prints is a real warning the program should fix.
logging.pattern.console=%level %logger{0}: %msg%nIf a warning does appear, it carries no timestamp, so the output is still comparable run to run.
spring.jpa.show-sql=trueEcho every SQL statement — the point of the module.
spring.jpa.open-in-view=falseSection 6 explains why you want this off anyway; here it also silences the warning Spring Boot prints when it is left on.
spring.jpa.hibernate.ddl-auto=create-dropBuild the schema from the mappings at start and drop it at close — which is why every output ends with drop table lines.
The warehouse as a Spring Boot application

The JPA module mapped the warehouse and drove it through an EntityManager by hand. This module keeps the same entities and lets Spring generate the boilerplate — and then shows what that costs when you stop paying attention:

  • ProductRepository is the first repository: an interface with no implementation, whose save, findById and findBySkuStartingWith all turn into SQL you can read (§2, §3, §4).
  • InventoryService is where @Transactional lives, and where a method that calls itself quietly runs outside any transaction (§5).
  • Order and OrderLine return for the N+1 problem — this time counted through Spring's statistics, with open-in-view switched off (§6).
  • The reports become pageable repository methods, projections, specifications and a keyset scroll (§7, §9).
  • StockLevel gains auditing columns and a domain event that fires only after the reservation commits (§8).
