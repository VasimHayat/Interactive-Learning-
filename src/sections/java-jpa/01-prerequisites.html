Before you begin

Prerequisites

This module assumes Java Fundamentals and Java Intermediate, or the equivalent. Java Advanced is not required, though §7 on locking reads more easily if you have met the lost-update problem there. Each item below is leaned on directly, with the section that taught it:

You also need basic SQL, stated plainly: you can read a select with a join and a where, you know what a primary key, a foreign key and an index are, and you know that a transaction either commits or rolls back. This module reads a great deal of SQL; it does not teach it.

What you need installed

A JDK 21 or newer, plus the library jars — this is the first module whose programs do not run on the JDK alone. If you are working from the course repository, one command resolves the exact versions the pages were built with into build/lib/java-jpa/:

node tools/fetch-deps.mjs java-jpa          # Hibernate 7.4.1, Jakarta Persistence 3.2, H2 2.4 and their runtime deps
javac -cp "build/lib/java-jpa/*" FirstEntity.java
java  -cp ".;build/lib/java-jpa/*" FirstEntity      # on Linux/macOS the separator is : not ;

With Maven or Gradle you need two coordinates; everything else arrives transitively:

<dependency><groupId>org.hibernate.orm</groupId><artifactId>hibernate-core</artifactId><version>7.4.1.Final</version></dependency>
<dependency><groupId>com.h2database</groupId><artifactId>h2</artifactId><version>2.4.240</version></dependency>

H2 is used because it needs no installation and starts in milliseconds. Every mapping here works unchanged on PostgreSQL or MySQL; where the generated SQL would differ, the text says so.

Three habits to unlearn

An ORM is convenient enough that it invites three assumptions, each of which works in a demo and fails in production:

  • "An entity is just a data holder." It is not. A managed entity is watched: change a field and the change is written at commit whether you meant it or not, and hand it to a view layer and the view can trigger queries. Entities are a persistence tool; records are for carrying data around (§3, §11).
  • "A collection on an entity is a collection." It is a promise to load one later, valid only while the session that made the promise is open. Touch it afterwards and you get LazyInitializationException; touch it in a loop and you get the N+1 problem (§5).
  • "hbm2ddl.auto=update keeps the schema in sync." It adds what is missing and never removes, renames or narrows anything, and it has no idea what your data means. It is a development convenience; a deployment is a migration script (§10).
