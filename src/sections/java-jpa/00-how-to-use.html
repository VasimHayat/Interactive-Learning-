How to use this module

Work through it at your own pace. Your section checkmarks, quiz answers, flashcard marks and notes are saved in this browser under a key scoped to this file, so closing the tab loses nothing and the earlier modules cannot overwrite it. Nothing is sent anywhere — this page makes no network requests at all. Press ? at any time for the keyboard shortcuts, and use Reset progress in the sidebar to start over.

Every program in this module was compiled and executed as part of the build, against a pinned stack: Hibernate ORM 7.4.1, Jakarta Persistence 3.2 and an in-memory H2 database, on JDK 21. That matters more here than in the earlier modules, because most of what you will read is not program output at all — it is SQL. Every line that begins Hibernate: in an Expected output block is a statement Hibernate actually sent to the database when the page was built, captured with hibernate.show_sql. The prose reads those statements line by line, and when a section claims that a mapping produces two queries instead of one, the count was checked by the build, not asserted by the author. Where a widget animates something — a persistence context filling up, a lock being lost — it carries the Simulated badge: nothing in a browser talks to a database.

The warehouse, finally persisted

Three modules of Product, Order and InventoryService have lived entirely in memory. This module puts them in a database and keeps the same vocabulary, so the mapping decisions are about types you already know:

  • Product becomes the first entity: a generated id, a unique sku, an enum stored as text, a price stored as cents, and value objects for money and dimensions (§1, §2).
  • Order and OrderLine become the first association, and the place where the owning side, cascades and lazy loading are learned the hard way (§3–§5).
  • StockLevel is the row two pickers fight over: it carries the @Version column that turns a lost update into an exception (§7).
  • Supplier is the many-to-many; Discount is the sealed hierarchy from Intermediate, mapped three different ways so you can compare the tables (§4, §8).
  • The reports from Intermediate are rewritten as JPQL, the Criteria API and projections, and then made fast with batching (§6, §9).
