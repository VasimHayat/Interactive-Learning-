Section 2

Mapping entities to tables

An entity is a class whose instances correspond to rows. The mapping says which class, which table, which field goes in which column with which type, and — the decision with the longest consequences — where the primary key comes from. Every annotation in this section is a sentence in that contract, and the generated DDL is the database's reading of it. The rules an entity class must obey come first, because Hibernate enforces them at bootstrap and the error messages assume you know them:

  • A no-argument constructor, at least protected. Hibernate instantiates the class reflectively when it loads a row, then sets the fields. The constructor you actually use can take whatever it likes.
  • Not final, and ideally no final methods: lazy loading (§5) works by subclassing the entity at runtime to make a proxy, and a final class cannot be subclassed.
  • Exactly one identifier — an @Id field (or an @EmbeddedId) — and it must not change once the row exists.
  • A top-level or static nested class. An inner class carries a hidden reference to its outer instance and cannot be instantiated without one.
  • Not a record. Records are final and immutable; an entity is neither, because Hibernate needs to set its id after insert and track changes to its fields. Records are the right type for everything an entity is not: projections, value objects passed around the application, API payloads (Intermediate §8, §11 here).

Worked example

One factory, three entities, three id strategies, and most of the column mappings you will ever need. Read the DDL Hibernate generated against the annotations that produced it — and watch where the inserts happen, because one of the three strategies changes when rows are written.

import jakarta.persistence.*;
import org.hibernate.annotations.NaturalId;

import java.math.BigDecimal;
import java.time.Instant;
import java.time.LocalDate;
import java.util.UUID;

public class Mapping {

    enum Category { FASTENER, STRUCTURAL, TOOLING }

    /** A value object stored inline in the owner's row: three columns, no identity, no table. */
    @Embeddable
    public static class Dimensions {
        private int widthMm, heightMm, depthMm;
        protected Dimensions() {}
        Dimensions(int w, int h, int d) { widthMm = w; heightMm = h; depthMm = d; }
        long volumeMm3() { return (long) widthMm * heightMm * depthMm; }
        @Override public String toString() { return widthMm + "x" + heightMm + "x" + depthMm + " mm"; }
    }

    /** A domain type the database never sees: the converter stores it as one bigint of cents. */
    record Money(long cents) {
        @Override public String toString() { return String.format("%d.%02d", cents / 100, cents % 100); }
    }
    @Converter(autoApply = true)
    public static class MoneyConverter implements AttributeConverter {
        @Override public Long convertToDatabaseColumn(Money m) { return m == null ? null : m.cents(); }
        @Override public Money convertToEntityAttribute(Long cents) { return cents == null ? null : new Money(cents); }
    }

    @Entity(name = "Product")
    @Table(name = "product")
    @Access(AccessType.FIELD)                                   // map fields, not getters
    public static class Product {
        @Id
        @GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "product_seq")
        @SequenceGenerator(name = "product_seq", sequenceName = "product_seq", allocationSize = 10)
        private Long id;

        @NaturalId                                              // Hibernate: a business key with its own lookup
        @Column(nullable = false, unique = true, length = 16)
        private String sku;

        @Basic(optional = false)
        @Column(length = 80)
        private String name;

        @Enumerated(EnumType.STRING)                            // never ORDINAL
        @Column(nullable = false, length = 20)
        private Category category;

        @Column(name = "unit_price")
        private Money unitPrice;                                // MoneyConverter applies automatically

        @Column(precision = 8, scale = 3)
        private BigDecimal weightKg;

        @Embedded
        @AttributeOverride(name = "widthMm",  column = @Column(name = "dim_w_mm"))
        @AttributeOverride(name = "heightMm", column = @Column(name = "dim_h_mm"))
        @AttributeOverride(name = "depthMm",  column = @Column(name = "dim_d_mm"))
        private Dimensions dimensions;

        private LocalDate introducedOn;                         // java.time maps directly: no @Temporal
        private Instant createdAt;

        @Transient
        private String label;                                   // derived, never a column

        protected Product() {}
        Product(String sku, String name, Category category, Money unitPrice, BigDecimal weightKg,
                Dimensions dimensions, LocalDate introducedOn, Instant createdAt) {
            this.sku = sku; this.name = name; this.category = category; this.unitPrice = unitPrice;
            this.weightKg = weightKg; this.dimensions = dimensions; this.introducedOn = introducedOn; this.createdAt = createdAt;
        }
        Long id() { return id; }
        String sku() { return sku; }
        Category category() { return category; }
        Money unitPrice() { return unitPrice; }
        BigDecimal weightKg() { return weightKg; }
        Dimensions dimensions() { return dimensions; }
        LocalDate introducedOn() { return introducedOn; }
        Instant createdAt() { return createdAt; }
        String label() {
            if (label == null) label = sku + " / " + name;      // computed on demand, cached in the object only
            return label;
        }
    }

    @Entity(name = "Warehouse")
    @Table(name = "warehouse")
    public static class Warehouse {
        @Id @GeneratedValue(strategy = GenerationType.IDENTITY)   // the database assigns the id at insert
        private Long id;
        @Column(nullable = false, length = 40)
        private String name;
        protected Warehouse() {}
        Warehouse(String name) { this.name = name; }
        Long id() { return id; }
    }

    @Entity(name = "AuditEvent")
    @Table(name = "audit_event")
    public static class AuditEvent {
        @Id @GeneratedValue(strategy = GenerationType.UUID)       // generated in the JVM, random
        private UUID id;
        @Column(nullable = false, length = 120)
        private String message;
        protected AuditEvent() {}
        AuditEvent(String message) { this.message = message; }
        UUID id() { return id; }
    }

    static EntityManagerFactory emf(Class... managed) {
        var cfg = new PersistenceConfiguration("warehouse")
            .property(PersistenceConfiguration.JDBC_URL, "jdbc:h2:mem:Mapping;DB_CLOSE_DELAY=-1")
            .property(PersistenceConfiguration.JDBC_USER, "sa")
            .property(PersistenceConfiguration.JDBC_PASSWORD, "")
            .property(PersistenceConfiguration.SCHEMAGEN_DATABASE_ACTION, "drop-and-create")
            .property("hibernate.show_sql", "true");
        for (Class c : managed) cfg.managedClass(c);
        return cfg.createEntityManagerFactory();
    }

    public static void main(String[] args) {
        try (EntityManagerFactory emf = emf(Product.class, Warehouse.class, AuditEvent.class, MoneyConverter.class)) {

            try (EntityManager em = emf.createEntityManager()) {
                em.getTransaction().begin();
                Product bolt = new Product("BOLT-7", "M8 hex bolt", Category.FASTENER, new Money(80),
                        new BigDecimal("0.012"), new Dimensions(8, 8, 40),
                        LocalDate.of(2024, 3, 1), Instant.parse("2026-10-15T08:30:00Z"));
                Warehouse main = new Warehouse("Main");
                AuditEvent event = new AuditEvent("catalogue seeded");
                em.persist(bolt);
                em.persist(main);
                em.persist(event);
                System.out.println("ids before commit: product=" + bolt.id() + " warehouse=" + main.id()
                        + " audit assigned=" + (event.id() != null));
                em.getTransaction().commit();
            }

            try (EntityManager em = emf.createEntityManager()) {
                Product p = em.find(Product.class, 1L);
                System.out.println("category   = " + p.category());
                System.out.println("unitPrice  = " + p.unitPrice());
                System.out.println("weightKg   = " + p.weightKg());
                System.out.println("dimensions = " + p.dimensions() + " -> " + p.dimensions().volumeMm3() + " mm3");
                System.out.println("introduced = " + p.introducedOn() + ", createdAt kept = "
                        + p.createdAt().equals(Instant.parse("2026-10-15T08:30:00Z")));
                System.out.println("label      = " + p.label());

                Object[] raw = (Object[]) em.createNativeQuery(
                        "select category, unit_price, dim_w_mm from product where id = 1").getSingleResult();
                System.out.println("raw row    = " + raw[0] + " | " + raw[1] + " | " + raw[2]);

                Product bySku = em.createQuery("select p from Product p where p.sku = :sku", Product.class)
                        .setParameter("sku", "BOLT-7").getSingleResult();
                System.out.println("by sku     = same instance: " + (bySku == p));
            }
        }
    }
}

Reading the DDL against the annotations:

  • create table product (dim_d_mm integer, dim_h_mm integer, dim_w_mm integer, …) — the @Embeddable Dimensions became three columns in the owner's table, renamed by @AttributeOverride. There is no dimensions table; a value object has no identity and no row of its own. (The scratch HTE_ table ignores the overrides — it is internal, never yours.)
  • weightKg numeric(8,3) from @Column(precision = 8, scale = 3); createdAt timestamp(6) with time zone from a plain Instant field and introducedOn date from a LocalDate. The java.time types need no @Temporal; that annotation exists for the legacy java.util.Date, which is ambiguous about what it stores.
  • category enum ('FASTENER','STRUCTURAL','TOOLING') not null — H2 and PostgreSQL have native enum types and Hibernate 7 uses them; on MySQL this is also enum, on Oracle a varchar2 with a check constraint. Either way the name is stored, because of EnumType.STRING. The gotcha callout below explains why the alternative is a trap.
  • unit_price bigint — the Money record exists only in Java. The @Converter(autoApply = true) turns it into a long on the way out and back on the way in, for every entity that has a Money field, with no annotation at the field. The native query confirms the column really holds 80.
  • name varchar(80) not null came from @Basic(optional = false); sku … not null unique from @Column. Both are hints that become real constraints only because schema generation ran. In production the constraints must exist in the migration script too (§10): Hibernate never checks them on read, and a null in a not null column from some other writer is still a bug on its way to you.
  • No label column. @Transient fields are invisible to the mapping; the field is recomputed lazily in each loaded instance.

Now the three id strategies, which is where the output stops being a transcript of DDL and becomes a transcript of timing:

  • Product: SEQUENCE. create sequence product_seq … increment by 10, then one select next value at persist. The id is known immediately — product=1 prints before commit — but the insert can wait, so it would be batched with others (§9).
  • Warehouse: IDENTITY. The column is generated by default as identity and the insert sends default for the id. The database assigns it, and Hibernate must read it back before it can register the entity — so the insert runs at persist, not at commit. Look at the order of the output: the product insert, which was queued, was forced out before the warehouse insert to keep the two in program order. IDENTITY makes write-behind impossible for that entity, and makes insert batching impossible with it (§9).
  • AuditEvent: UUID. Generated in the JVM, random, assigned at persist with no database call at all; its insert waits for commit like the sequence-backed one. The value is random, so the program prints only audit assigned=true. Random UUIDs are convenient and terrible for index locality on large tables, as the sandbox explains.

Two last lines. The native query shows the raw row: the enum as text, the money as an integer, the embedded width as its own column. And the JPQL lookup by sku returned the same instance as find had — not an equal object, the same reference. That is the persistence context's identity guarantee, and §3 is about it.

What each id strategy costs

The identifier strategy is the mapping decision you cannot cheaply change later, because the key is in every foreign key. Pick the strategy and the database, and read the consequences.

Naming. With no naming strategy configured, a field priceInCents becomes a column priceInCents, which most databases fold to PRICEINCENTS or quote awkwardly. Set hibernate.physical_naming_strategy to CamelCaseToUnderscoresNamingStrategy and it becomes price_in_cents everywhere, with no @Column(name = …) on every field. Spring Boot does this by default, which is why Spring projects' tables look different from these.

Mapping gotchas
  • EnumType.ORDINAL is a time bomb. It stores 0, 1, 2. Insert a constant in the middle of the enum and every existing row silently means something else. STRING costs a few bytes and survives any reordering; renaming a constant is then a one-line migration you can see.
  • IDENTITY forces an early insert and disables batching. It is the right choice only when the database offers nothing else, or when writes are rare. On MySQL, where sequences do not exist, know that SEQUENCE silently becomes a table generator — check the DDL.
  • A random UUID key scatters the index. Each insert lands on a random page of the primary-key B-tree. Fine at thousands of rows, painful at hundreds of millions; time-ordered UUIDs fix it.
  • @Column hints are not validation. length = 16 becomes varchar(16) in generated DDL and nothing else: a longer string is rejected by the database, not by Hibernate, and only if the constraint actually exists. Validate in Java (Bean Validation integrates) and constrain in the schema.
  • Default varchar(255). Every unannotated String. Set a length deliberately, or use @Lob/columnDefinition = "text" for real text.
  • java.util.Date and Calendar need @Temporal and still lose the zone. Use Instant for a point in time, LocalDate for a calendar date, and store instants in UTC (Intermediate §12). Hibernate 7's hibernate.timezone.default_storage defaults to normalising to UTC.

Check yourself

1.In the worked example the insert into product ran before ids before commit was printed, even though the product uses SEQUENCE and inserts are normally deferred to commit. What forced it out early?

B. persist(main) on the IDENTITY-keyed Warehouse cannot complete without the database-generated id, so its insert executes at once — and Hibernate executes earlier queued inserts first rather than reorder them. The AuditEvent, persisted last, waited for commit as usual.

A: one id was used out of a block of ten. C: reading a field is plain Java; Hibernate does not intercept it. D: @NaturalId affects lookups and caching, not insert timing — uniqueness is checked by the database constraint whenever the insert runs.

2.A team stored Category with the default @Enumerated, then added PACKAGING between FASTENER and STRUCTURAL in the enum. What happens to existing rows?

C. The default is ORDINAL: the column holds a position, and positions shifted. No error anywhere — the data just means something different now. This is why EnumType.STRING is the rule.

A describes what you might wish ordinals did. B: Hibernate has no way to know what the numbers meant before. D is what STRING mapping does when a stored name no longer exists — loud, and therefore safe.

3.Which statements about @Embeddable are true? Select all that apply.

A and C. An embeddable is a value object: the Dimensions columns live in product, and the object is compared by its fields, never by a key. It is the ORM's answer to the granularity mismatch.

B describes a @OneToOne entity (§4). D is the opposite of the point: an embeddable with an @Id is a mapping error — if it needs identity it is an entity.
