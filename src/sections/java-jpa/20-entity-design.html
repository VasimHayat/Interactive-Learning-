Section 11

Designing entities: identity, equality and callbacks

An entity has three notions of "the same" and they do not agree. Database identity is the primary key: two rows are the same row if their ids match. Object identity is ==: inside one persistence context Hibernate guarantees one Java object per row (§3), so == works there and nowhere else — the same row loaded in two contexts is two objects. Equality is equals/hashCode, which you write, and which Set, Map and every contains call will trust completely.

The difficulty is that a generated id does not exist until the entity is persisted, and hashCode must never change while an object sits in a hash-based collection. Those two facts collide in a bug that is easy to write, invisible in tests that only use lists, and baffling in production.

Worked example: three ways to write equals, and the one that breaks

import jakarta.persistence.*;
import org.hibernate.Session;
import org.hibernate.annotations.Immutable;
import org.hibernate.annotations.NaturalId;
import org.hibernate.annotations.SQLDelete;
import org.hibernate.annotations.SQLRestriction;

import java.time.Instant;
import java.util.HashSet;
import java.util.Objects;
import java.util.Set;

public class EntityDesign {

    /* Option 1 — equals/hashCode on the generated id. Looks obvious, breaks in a Set. */
    @Entity(name = "IdHashProduct")
    @Table(name = "id_hash_product")
    public static class IdHashProduct {
        @Id @GeneratedValue(strategy = GenerationType.SEQUENCE) Long id;
        @Column(nullable = false, length = 16) String sku;
        protected IdHashProduct() {}
        IdHashProduct(String sku) { this.sku = sku; }
        @Override public boolean equals(Object o) { return o instanceof IdHashProduct p && Objects.equals(id, p.id); }
        @Override public int hashCode() { return Objects.hashCode(id); }
    }

    /* Option 2 — a business key that never changes. */
    @Entity(name = "SkuProduct")
    @Table(name = "sku_product")
    public static class SkuProduct {
        @Id @GeneratedValue(strategy = GenerationType.SEQUENCE) Long id;
        @Column(nullable = false, unique = true, length = 16) String sku;
        protected SkuProduct() {}
        SkuProduct(String sku) { this.sku = sku; }
        @Override public boolean equals(Object o) { return o instanceof SkuProduct p && sku.equals(p.sku); }
        @Override public int hashCode() { return sku.hashCode(); }
    }

    /* Option 3 — id equality once assigned, a constant hash so the bucket never moves. */
    @Entity(name = "SafeProduct")
    @Table(name = "safe_product")
    public static class SafeProduct {
        @Id @GeneratedValue(strategy = GenerationType.SEQUENCE) Long id;
        @Column(nullable = false, length = 16) String sku;
        protected SafeProduct() {}
        SafeProduct(String sku) { this.sku = sku; }
        @Override public boolean equals(Object o) { return o instanceof SafeProduct p && id != null && id.equals(p.id); }
        @Override public int hashCode() { return getClass().hashCode(); }
    }

    /* Auditing: callbacks on the entity plus an external listener. */
    public static class AuditListener {
        static int prePersist, preUpdate;
        @PrePersist void beforeInsert(Object e) { prePersist++; }
        @PreUpdate  void beforeUpdate(Object e) { preUpdate++; }
    }

    @Entity(name = "AuditedProduct")
    @Table(name = "audited_product")
    @EntityListeners(AuditListener.class)
    public static class AuditedProduct {
        @Id @GeneratedValue(strategy = GenerationType.SEQUENCE) Long id;
        @NaturalId @Column(nullable = false, length = 16) String sku;
        int priceInCents;
        @Column(nullable = false, updatable = false) Instant createdAt;
        @Column(nullable = false) Instant updatedAt;
        protected AuditedProduct() {}
        AuditedProduct(String sku, int priceInCents) { this.sku = sku; this.priceInCents = priceInCents; }
        @PrePersist void stamp() { createdAt = updatedAt = Instant.now(); }
        @PreUpdate  void touch() { updatedAt = Instant.now().plusSeconds(1); }   // +1s so the fact below cannot tie
    }

    /* Soft delete: DELETE becomes UPDATE, and every query gets a filter for free. */
    @Entity(name = "SoftProduct")
    @Table(name = "soft_product")
    @SQLDelete(sql = "update soft_product set deleted = true where id = ?")
    @SQLRestriction("deleted = false")
    public static class SoftProduct {
        @Id @GeneratedValue(strategy = GenerationType.SEQUENCE) Long id;
        @Column(nullable = false, length = 16) String sku;
        boolean deleted;
        protected SoftProduct() {}
        SoftProduct(String sku) { this.sku = sku; }
    }

    /* Reference data that never changes: Hibernate skips dirty checking entirely. */
    @Entity(name = "Currency")
    @Table(name = "currency")
    @Immutable
    public static class Currency {
        @Id @Column(length = 3) String code;
        String name;
        protected Currency() {}
        Currency(String code, String name) { this.code = code; this.name = name; }
    }

    static EntityManagerFactory emf(boolean showSql, Class... entities) {
        var cfg = new PersistenceConfiguration("warehouse")
            .property(PersistenceConfiguration.JDBC_URL, "jdbc:h2:mem:EntityDesign;DB_CLOSE_DELAY=-1")
            .property(PersistenceConfiguration.JDBC_USER, "sa")
            .property(PersistenceConfiguration.JDBC_PASSWORD, "")
            .property(PersistenceConfiguration.SCHEMAGEN_DATABASE_ACTION, "drop-and-create")
            .property("hibernate.show_sql", String.valueOf(showSql));
        for (Class c : entities) cfg.managedClass(c);
        return cfg.createEntityManagerFactory();
    }

    public static void main(String[] args) {
        System.out.println("-- equality: add to a Set before persist, look it up after --");
        try (EntityManagerFactory emf = emf(false, IdHashProduct.class, SkuProduct.class, SafeProduct.class)) {
            IdHashProduct a = new IdHashProduct("BOLT-7");
            SkuProduct b = new SkuProduct("BOLT-7");
            SafeProduct c = new SafeProduct("BOLT-7");
            Set setA = new HashSet<>(Set.of(a));
            Set setB = new HashSet<>(Set.of(b));
            Set setC = new HashSet<>(Set.of(c));
            try (EntityManager em = emf.createEntityManager()) {
                em.getTransaction().begin();
                em.persist(a); em.persist(b); em.persist(c);
                em.getTransaction().commit();
            }
            System.out.println("id-based hashCode : id=" + a.id + ", set.contains = " + setA.contains(a));
            System.out.println("business key      : id=" + b.id + ", set.contains = " + setB.contains(b));
            System.out.println("id + constant hash: id=" + c.id + ", set.contains = " + setC.contains(c));

            try (EntityManager em = emf.createEntityManager()) {          // a second context: a different Java object
                SafeProduct reloaded = em.find(SafeProduct.class, c.id);
                System.out.println("reloaded == c: " + (reloaded == c) + ", reloaded.equals(c): " + reloaded.equals(c)
                        + ", set.contains(reloaded): " + setC.contains(reloaded));
            }
            System.out.println("two transient SafeProducts equal: " + new SafeProduct("X").equals(new SafeProduct("X")));
        }

        System.out.println("-- callbacks, soft delete, immutable, natural id --");
        try (EntityManagerFactory emf = emf(true, AuditedProduct.class, SoftProduct.class, Currency.class)) {
            System.out.println("- @PrePersist / @PreUpdate -");
            Long auditedId;
            try (EntityManager em = emf.createEntityManager()) {
                em.getTransaction().begin();
                AuditedProduct p = new AuditedProduct("BOLT-7", 80);
                em.persist(p);
                em.getTransaction().commit();
                auditedId = p.id;
                System.out.println("createdAt set: " + (p.createdAt != null) + ", createdAt equals updatedAt: " + p.createdAt.equals(p.updatedAt));
            }
            try (EntityManager em = emf.createEntityManager()) {
                em.getTransaction().begin();
                AuditedProduct p = em.find(AuditedProduct.class, auditedId);
                p.priceInCents = 90;
                em.getTransaction().commit();
                System.out.println("updatedAt moved after update: " + p.updatedAt.isAfter(p.createdAt));
            }
            System.out.println("listener calls: prePersist=" + AuditListener.prePersist + ", preUpdate=" + AuditListener.preUpdate);

            System.out.println("- @NaturalId lookup -");
            try (EntityManager em = emf.createEntityManager()) {
                AuditedProduct p = em.unwrap(Session.class).byNaturalId(AuditedProduct.class).using("sku", "BOLT-7").load();
                System.out.println("by natural id: " + p.sku + " at " + p.priceInCents + "c");
            }

            System.out.println("- soft delete -");
            Long softId;
            try (EntityManager em = emf.createEntityManager()) {
                em.getTransaction().begin();
                SoftProduct s = new SoftProduct("NUT-3");
                em.persist(s);
                em.getTransaction().commit();
                softId = s.id;
            }
            try (EntityManager em = emf.createEntityManager()) {
                em.getTransaction().begin();
                em.remove(em.find(SoftProduct.class, softId));
                em.getTransaction().commit();
            }
            try (EntityManager em = emf.createEntityManager()) {
                long jpql = em.createQuery("select count(s) from SoftProduct s", Long.class).getSingleResult();
                Number sql = (Number) em.createNativeQuery("select count(*) from soft_product").getSingleResult();
                System.out.println("JPQL count = " + jpql + ", native count = " + sql);
            }

            System.out.println("- @Immutable: a change is silently ignored -");
            try (EntityManager em = emf.createEntityManager()) {
                em.getTransaction().begin();
                em.persist(new Currency("GBP", "Pound sterling"));
                em.getTransaction().commit();
            }
            try (EntityManager em = emf.createEntityManager()) {
                em.getTransaction().begin();
                Currency gbp = em.find(Currency.class, "GBP");
                gbp.name = "changed";
                em.getTransaction().commit();
            }
            try (EntityManager em = emf.createEntityManager()) {
                System.out.println("GBP name = " + em.find(Currency.class, "GBP").name);
            }
        }
    }
}

The first block is the whole argument. All three products were put in a HashSet while transient, then persisted. Option 1 hashed null before persist (bucket 0) and hashes 1 after, so the set looks in the wrong bucket: contains is false for an object that is in the set. Nothing threw; the entity is simply stranded in a bucket it will never be found in, and remove will fail the same way, so the set can never be cleaned. Option 2 hashes the SKU, which was known from construction and never changes: correct, provided your entity has an immutable business key. Option 3 is the general answer when it does not: hashCode is a constant per class, so the bucket never moves, and equals compares ids once both are assigned — which the second context proves, where reloaded is a different object (== false) but equal to c and found in the set. The price is that every instance lands in one bucket, so a HashSet of these degrades to a list; for the handful of entities a @OneToMany typically holds, that is irrelevant. The last line is the one subtlety: two transient instances are never equal under option 3, because neither has an id yet — deliberate, since two unsaved products are two products.

The second block covers the supporting cast. @PrePersist stamped both timestamps before the INSERT (the output confirms they were set and equal) and @PreUpdate moved updatedAt before the UPDATE; the external listener counted one of each. The @NaturalId lookup went to the database by sku rather than by id, and would have consulted the natural-id cache first had one been configured. The soft delete turned remove into the UPDATE you wrote, and the @SQLRestriction was appended to the find, the count — every entity query — while the native query saw the row that is still physically there. And the @Immutable currency was changed and committed with no UPDATE at all: Hibernate takes no snapshot of an immutable entity, so there is nothing to dirty-check.

Value objects, boundaries and the shape of an entity

// A value object has no identity: equal by value, immutable, embedded in the owning row.
// Hibernate 6.2+ maps a record directly as an embeddable.
@Embeddable
public record Money(long amountInCents, String currency) {
    public Money { if (amountInCents < 0) throw new IllegalArgumentException("negative"); }
}

@Entity
public class OrderLine {
    @Id @GeneratedValue(strategy = GenerationType.SEQUENCE) private Long id;
    @Embedded private Money unitPrice;              // columns unitPrice_amountInCents, unitPrice_currency
    @Embedded @AttributeOverride(name = "amountInCents", column = @Column(name = "discount_cents"))
              @AttributeOverride(name = "currency",      column = @Column(name = "discount_ccy"))
    private Money discount;
    ...
}

// At the boundary, the entity never leaves the service:
public record OrderSummary(Long id, String customer, long totalInCents) {}
public OrderSummary summary(long id) {
    Order o = em.find(Order.class, id);
    return new OrderSummary(o.getId(), o.getCustomer().getName(), o.total().amountInCents());
}

Three design pressures pull on an entity. First, push value semantics into value objects: money, a date range, an address, a quantity with its unit are not rows with identity; they are values, best modelled as records marked @Embeddable, equal by their fields and impossible to put into an inconsistent state. Second, keep entities inside the persistence boundary. An entity handed to a JSON serializer or a view template will trigger lazy loads outside the transaction (LazyInitializationException, §5), will serialize a bidirectional association forever (Order → lines → order → lines…), and will send every column to a client that wanted three. Map to a DTO at the service edge; the projection queries from §9 often make the entity unnecessary for reads altogether. Third, the rich-versus-anaemic argument: an entity that enforces its own invariants (order.addLine(...) checks stock and keeps both sides of the association in sync, §4) is easier to keep correct than a bag of getters and setters driven by a service, but entities that reach for repositories or external services from inside their methods become untestable. A reasonable line: invariants and state transitions live in the entity; coordination, transactions and I/O live in the service.

Callbacks on the entity are fine for stamping; @EntityListeners moves the same logic into a reusable class — the worked example's AuditListener — that can be applied to every audited entity, usually through a @MappedSuperclass that carries createdAt/updatedAt/createdBy. Hibernate adds @CreationTimestamp and @UpdateTimestamp for the two commonest cases, and Envers (hibernate-envers, @Audited) for full history tables: every change to an audited entity is recorded in a _AUD table with a revision number, and you can query "what did this order look like at revision 17". Not on this page's class path, but the first thing to reach for when the requirement is "who changed what, when" rather than "when was it last changed".

Soft delete, honestly

Soft delete keeps the row and hides it, which auditors, undo features and foreign keys from other tables all like. It also costs more than the two annotations suggest. A unique constraint on sku now blocks re-creating a deleted product, so the constraint must become (sku, deleted) or a partial index. Every association to a soft-deletable entity needs the restriction too, or an Order will happily join to its deleted lines — and @SQLRestriction on the collection side is a separate declaration. Reports that must include deleted rows need native SQL or a second entity mapped without the restriction. And remove still fires @PreRemove, still cascades, still orphan-removes, exactly as if the row were gone. Hibernate 6.4 added @SoftDelete, which handles the column, the restriction and the collection cases together; prefer it to hand-rolled @SQLDelete when you are on a version that has it.

Entity design gotchas
  • Lombok @Data on an entity generates equals/hashCode over every field, including the generated id and lazy collections. That is option 1's bug plus a lazy-load (or a StackOverflowError through a bidirectional association) every time hashCode runs. Use @Getter/@Setter and write the two methods by hand.
  • final classes and final methods cannot be proxied, so lazy loading of a @ManyToOne to them silently becomes eager. Records cannot be entities for the same reason (and because they are immutable with no no-arg constructor); they are excellent embeddables and projections.
  • toString() that touches a collection loads it. A log statement at the wrong place becomes a query, or a LazyInitializationException.
  • Timestamps set in Java are the application's clock, not the database's. For ordering across servers prefer a database default or @CurrentTimestamp(source = SourceType.DB).
  • @DynamicInsert omits null columns so database defaults apply — and then the entity in memory still holds null until you refresh it.
  • A @NaturalId is immutable by default. Changing it throws unless you declare @NaturalId(mutable = true), and a mutable natural id is a poor hashCode ingredient for the reason this whole section is about.

Check yourself

1.An Order entity has @OneToMany Set<OrderLine> lines. OrderLine.hashCode() returns Objects.hash(id). A service creates a new line, adds it to order.getLines(), and calls em.persist(line). Later in the same transaction, order.getLines().remove(line) returns false and the line is still there. Why?

C. Exactly the stepper. The hash changed between add and remove, so the set looks in the wrong bucket. A business-key or constant hashCode would have kept the bucket stable.

A is false: Hibernate's PersistentSet supports removal. B is invented. D is a real rule (§4) but affects what is written, not whether a Java Set can find its own element.

2.With @SQLDelete and @SQLRestriction("deleted = false") on Product, which query can still return a soft-deleted product?

B. The restriction is appended to SQL that Hibernate generates. Native SQL is yours verbatim, which the worked example showed with its count(*) of 1 against a JPQL count of 0. Native queries that should respect soft delete must say so themselves.

A, C and D are all generated by Hibernate from the mapping and all carry the deleted = false predicate — the find in the output shows it in its where clause.

3.Which statements about lifecycle callbacks are true? Select all that apply.

A and D. Callbacks hang off the persistence context's own operations: dirty checking decides whether an UPDATE (and so @PreUpdate) happens, and listeners are plain classes attached by annotation to as many entities as you like.

B is false: the stateless session bypasses the persistence context and its events, which is part of why it is fast. C is false: a bulk statement is one SQL statement that never loads the entities, so no per-entity callback can run — the updatedAt column stays stale unless the statement sets it.
