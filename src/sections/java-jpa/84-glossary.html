Reference

Glossary

Thirty terms, each linked back to the section that introduces it. The same entries drive the flashcard deck below — one list, two ways to use it.

Flashcards

Bag
Hibernate's name for a List collection mapping without an @OrderColumn: unordered, duplicates allowed. Removing one element can delete and re-insert the rest, and two bags cannot be fetch-joined in one query (MultipleBagFetchException). §4
Batch fetching
Loading lazy collections or proxies for several parents at once with where id in (?, …), via @BatchSize or session.setFetchBatchSize. Turns 1 + N statements into 1 + ⌈N / size⌉ with no change to the query. §5
Cascade
Propagating an EntityManager operation along an association: cascade = PERSIST persists the children with the parent, REMOVE deletes them with it. Right for owned children; wrong — and destructive — on references to shared entities. §4
Criteria API
Building a JPQL-equivalent query from Java objects (CriteriaBuilder, Root, Predicate) instead of a string. The right tool when the query's shape depends on which filters the caller supplied; verbose for anything static. §6
Dirty checking
At flush, Hibernate compares every managed entity with the snapshot taken when it was loaded and emits an update for each one that differs — all columns by default. It is why a plain setter on a managed entity reaches the database without any "save" call. §3
Discriminator
The column in a SINGLE_TABLE hierarchy that records which subclass a row is (@DiscriminatorColumn / @DiscriminatorValue). Hibernate 7 adds a check constraint on its values and filters by it for subtype queries. §8
Entity graph
A declared fetch plan — which attributes to load with the root — applied to a query or a find as the jakarta.persistence.fetchgraph or loadgraph hint. The same SQL join as join fetch, kept out of the query text so one query can serve several screens. §5
Entity states
Transient: a new object with no row. Managed: tracked by a context, dirty-checked at flush. Detached: has a row, no context watching it. Removed: scheduled for deletion. Every EntityManager method is a transition between them. §3
EntityManagerFactory
Hibernate's SessionFactory: the thread-safe, expensive, application-scoped object holding the metamodel, dialect, connection pool and second-level cache. Build one per application; create a cheap EntityManager from it per unit of work. §1
First-level cache
The persistence context's identity map: within one EntityManager, a second find for the same id returns the same instance with no SQL. Gives repeatable reads for free — and stale ones if another transaction wrote in between. §3
Flush
Turning the queued inserts, updates and deletes into SQL — at commit, before a query that could see them (FlushModeType.AUTO), or on flush(). Statements run in a fixed order (inserts, updates, collection changes, deletes), not the order you called the methods. §7
Impedance mismatch
The five ways objects and rows disagree — identity, associations, granularity, inheritance, navigation — that an object-relational mapper exists to translate across, and that every later section is a consequence of. §1
JDBC batching
Sending many parameter sets for one statement in a single round trip (hibernate.jdbc.batch_size, with order_inserts/order_updates). Needs write-behind, so it is impossible with IDENTITY ids; invisible to show_sql, visible in Statistics. §9
Join fetch
select o from Order o join fetch o.lines: load the association in the same statement as the root. One query instead of N+1; inner join unless written left join fetch; cannot be combined with database-side pagination. §5
JPQL
The Jakarta Persistence Query Language: SQL-like syntax over entities and their attributes rather than tables and columns, translated per dialect by Hibernate (whose superset is HQL). Paths become joins, collection predicates become subqueries, select new becomes a DTO. §6
Mapped superclass
A class whose mapped fields are copied into every entity table that extends it (@MappedSuperclass). Not an entity: no table, no queries against it, no associations to it. The tool for shared audit columns, not for polymorphism. §8
mappedBy
Marks the inverse side of a bidirectional association, naming the owning field on the other entity. Hibernate reads and cascades through it but never writes from it — set only this side and the foreign key stays null. §4
Merge
em.merge(detached) copies the argument's state onto a managed instance (loading it first if needed) and returns that instance; the argument stays detached. Copies every field, so a partially filled object overwrites the rest of the row. §3
Migration
A versioned, reviewed, checksummed DDL script applied in order by a tool such as Flyway or Liquibase. The only safe way to change a production schema; hbm2ddl.auto=update is not one, because it can only add. §10
N+1 problem
One query for N parents and then one more per parent as each lazy association is touched. The most common JPA performance bug; detected by counting statements, fixed per query with join fetch, an entity graph, batch fetching or a DTO — never with EAGER. §5
Natural id
A unique, immutable business key such as a SKU, marked @NaturalId (Hibernate). Gets its own lookup API and cache region, and is the best candidate for equals/hashCode when one exists. §2
Optimistic locking
Detecting rather than preventing concurrent updates: a @Version column goes into every update's where clause, a stale version matches zero rows, and Hibernate throws OptimisticLockException. No locks, no waiting; the loser retries. §7
Orphan removal
orphanRemoval = true: removing a child from the parent's collection deletes its row at flush. For children that cannot exist without their parent; distinct from cascade = REMOVE, which fires only when the parent itself is removed. §4
Owning side
The side of an association whose field maps to the foreign-key column or join table — the many side of one-to-many, the @JoinTable side of many-to-many, the @JoinColumn side of one-to-one. Only its state is written to the database. §4
Persistence context
What an EntityManager owns: an identity map (one instance per id) plus a snapshot of each managed entity's loaded state, and a queue of pending writes. The source of the identity guarantee, dirty checking and write-behind. §3
Pessimistic locking
LockModeType.PESSIMISTIC_WRITE → select … for update: the database locks the row until commit and other lockers wait, then time out. Prevents conflicts instead of detecting them; needs a timeout and a consistent lock order to avoid deadlocks. §7
Projection
A query that returns scalars, a Tuple or a DTO (select new …) instead of entities. Nothing is hydrated or dirty-checked and nothing can lazy-load later — the right shape for read-only screens and reports. §6
Proxy
A runtime subclass (ByteBuddy) standing in for an entity or collection that has not been loaded; the first access to anything but the id runs the select. Why entities cannot be final, why getClass() lies, and what LazyInitializationException is thrown by. §5
Second-level cache
An optional, provider-backed cache of entity state by primary key, shared across persistence contexts for @Cacheable entities. Does not cache queries; is left stale by writes that bypass Hibernate. Worth it for immutable reference data, measured with statistics. §9
Soft delete
Marking a row deleted instead of removing it: @SQLDelete turns remove into an update, @SQLRestriction hides the row from find and JPQL. Native SQL still sees it, and unique constraints and joins need thought. §11
