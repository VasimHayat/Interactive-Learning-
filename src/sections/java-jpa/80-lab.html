Put it together

Hands-on lab: persisting the warehouse

Six steps that take the warehouse from in-memory collections to a real schema, with the three things a persistence layer must get right: a mapping that says what it means, stock that cannot be oversold, and reports that do not quietly run four hundred queries. Each step uses tools from one or two sections above and has a trap that the collections version never had. Write each one before opening its solution, and keep show_sql on while you do — the SQL is how you check your work.

Starter
mkdir warehouse-lab && cd warehouse-lab
# one file, WarehouseLab.java, grown step by step; LIB holds the jars from §1
javac -cp "$LIB/*" WarehouseLab.java && java -cp ".;$LIB/*" WarehouseLab      # on Linux/macOS the separator is :

Hibernate 7.4, JPA 3.2 and H2 as pinned in §1. The finished program below prints only facts and sorted data, so you can diff your run against it; it keeps show_sql off because six tables of DDL would bury the facts — the sections above have already shown you every statement shape it issues.

Step 1 — a product that knows what it is §2

Map Product with a SEQUENCE id, a sku that is both a unique column and Hibernate's @NaturalId, a Category enum stored as its name, and the price as an embedded Money value object (amount in cents plus currency). Then map StockLevel so that its primary key is the product's id, with a @Version column you will need in step 3.

Solution — step 1
@Embeddable
public record Money(long amountInCents, String currency) {}     // a record is a fine embeddable in Hibernate 6.2+

@Entity(name = "Product") @Table(name = "product")
public static class Product {
    @Id @GeneratedValue(strategy = GenerationType.SEQUENCE) private Long id;
    @NaturalId @Column(nullable = false, unique = true, length = 16) private String sku;
    @Enumerated(EnumType.STRING) @Column(nullable = false, length = 16) private Category category;
    @Embedded private Money price;
    …
}

@Entity(name = "StockLevel") @Table(name = "stock_level")
public static class StockLevel {
    @Id private Long id;                                     // not generated …
    @OneToOne(fetch = FetchType.LAZY) @MapsId private Product product;   // … it is copied from the product
    private int onHand;
    @Version private int version;
}

@MapsId is the shared-primary-key one-to-one: no separate product_id column, no way to have a stock row for a product that does not exist, and a find(StockLevel.class, productId) that needs no join. EnumType.STRING costs a few bytes per row and survives reordering the enum; the default ORDINAL silently corrupts data the day someone inserts a constant in the middle.

Step 2 — orders, lines and suppliers §4

Order owns its OrderLines: bidirectional, cascade everything, orphan removal on, with addLine/removeLine helpers so the two sides can never disagree. The line copies the unit price at the time of the order. Supplier is many-to-many with Product through a join table — choose the collection type on the owning side deliberately. Remember that ORDER is a reserved word.

Solution — step 2
@Entity(name = "Order") @Table(name = "orders")
public static class Order {
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true) @OrderBy("id")
    private List<OrderLine> lines = new ArrayList<>();
    void addLine(Product p, int qty) { lines.add(new OrderLine(this, p, qty, p.price().amountInCents())); }
    void removeLine(OrderLine l) { lines.remove(l); l.order = null; }
}

@Entity(name = "OrderLine") @Table(name = "order_line")
public static class OrderLine {
    @ManyToOne(fetch = FetchType.LAZY, optional = false) private Order order;     // the owning side: this column is the FK
    @ManyToOne(fetch = FetchType.LAZY, optional = false) private Product product;
    private long unitPriceInCents;                                            // history must not change when the price does
}

@Entity(name = "Supplier") @Table(name = "supplier")
public static class Supplier {
    @ManyToMany @JoinTable(name = "supplier_product",
        joinColumns = @JoinColumn(name = "supplier_id"), inverseJoinColumns = @JoinColumn(name = "product_id"))
    private Set<Product> products = new HashSet<>();
}

The constructor of OrderLine sets order, and addLine adds to the list: both sides, always, in one place. Cascade lives on the parent-to-child side only; a @ManyToOne with cascade = ALL would delete the product when a line is removed. The Set matters: with a List, removing one product from a supplier deletes every join row and reinserts the survivors.

Step 3 — stock that cannot be oversold §3, §7

Write reserve(sku, qty) twice. The pessimistic version loads the StockLevel with PESSIMISTIC_WRITE — a select … for update — so a second reservation waits. The optimistic version loads it normally and relies on @Version: if someone else committed first, the commit fails with OptimisticLockException, and you retry once in a fresh context. Prove the retry by having another transaction change the row between your read and your commit.

Solution — step 3
StockLevel s = em.find(StockLevel.class, productId, LockModeType.PESSIMISTIC_WRITE);   // pessimistic: nobody else may read-for-update until commit
s.take(qty);

while (true) {                                                                       // optimistic: read, change, let the version decide
    attempts++;
    try {
        if (!em.getTransaction().isActive()) em.getTransaction().begin();
        em.find(StockLevel.class, productId).take(qty);
        em.getTransaction().commit();                                                // update … where id=? and version=?
        return attempts;
    } catch (RollbackException e) {
        if (!(e.getCause() instanceof OptimisticLockException)) throw e;
        em.close(); em = emf.createEntityManager();                                  // the stale context is useless now
    }
}

Both are correct; they fail differently. Pessimistic serialises the two reservations in the database and costs a lock held for the transaction. Optimistic lets both proceed and refuses the loser at commit — cheaper when conflicts are rare, and the retry must start from a new context, because the old one still holds the stale row. After the second failure, the version check is the only thing standing between you and an oversold warehouse.

Step 4 — reports without an N+1 §5, §6

Three queries: revenue per category as a DTO (select new into a record, grouped and summed in the database); the two most expensive products with pagination; and every order with its lines and their products, listed in one statement. Prove the last claim with Statistics.getPrepareStatementCount().

Solution — step 4
select new WarehouseLab$CategoryRevenue(p.category, sum(l.qty * l.unitPriceInCents))   // a nested record: use its binary name
from OrderLine l join l.product p group by p.category order by p.category

select p from Product p order by p.price.amountInCents desc, p.sku        // then setFirstResult(0).setMaxResults(2)

select distinct o from Order o join fetch o.lines l join fetch l.product order by o.placed

The projection never materialises an entity: no persistence context entry, no dirty checking, exactly the columns the report needs. The ordered-and-limited query is the only correct pagination — getResultList().subList(…) loads the whole table. The double join fetch brings lines and products in the same result set, so touching them later costs nothing; without it the loop would run one query per order for the lines and one per line for the product. distinct keeps Hibernate from handing you the same order once per line.

Step 5 — importing five hundred products §9

Insert 500 products in one transaction without the context growing to 500 managed entities and without 500 round trips. Use a second EntityManagerFactory configured for writes — JDBC batching at 50, ordered inserts — flush and clear every 50, and report how many statements Hibernate actually prepared.

Solution — step 5
EntityManagerFactory bulk = base("none")                       // same database, no schema action this time
    .property("hibernate.jdbc.batch_size", "50")
    .property("hibernate.order_inserts", "true")
    .createEntityManagerFactory();

for (int i = 1; i <= 500; i++) {
    em.persist(new Product("IMP-" + i, …));
    if (i % 50 == 0) { em.flush(); em.clear(); }               // one batch out, context emptied
}

Twenty statements for five hundred rows: ten batched inserts of fifty, and ten select next value calls, because the sequence hands out fifty ids per call (§2). An IDENTITY id would have made batching impossible — Hibernate must insert each row to learn its key. The flush-and-clear keeps dirty checking cheap: a context holding ten thousand entities checks ten thousand snapshots at every flush.

Step 6 — auditing and soft delete §10, §11

Give Product createdAt/updatedAt timestamps and a revision counter maintained by lifecycle callbacks, not by every caller. Then make em.remove(product) a soft delete: the row stays, flagged, and disappears from every JPQL query — while a native count still sees it.

Solution — step 6
@Entity(name = "Product") @Table(name = "product")
@SQLDelete(sql = "update product set deleted = true where id = ?")     // what remove() issues instead of DELETE
@SQLRestriction("deleted = false")                                     // appended to every query and find
public static class Product {
    private boolean deleted;
    private Instant createdAt, updatedAt;
    private int revision;
    @PrePersist void onCreate() { createdAt = updatedAt = Instant.now(); }
    @PreUpdate  void onUpdate() { updatedAt = Instant.now(); revision++; }
}

Callbacks run inside the flush, so no caller can forget them, and @PreUpdate fires only when dirty checking found a real change. The two Hibernate annotations make soft delete a mapping concern rather than a where deleted = false that every query must remember. The native count is the reminder that the restriction is Hibernate's, not the database's: reports written in SQL, and other applications, still see the row.

The finished thing

All six steps assembled. This program is compiled and run against the pinned Hibernate and H2 during the build of this page, so every number below is what it really printed.

import jakarta.persistence.*;
import org.hibernate.SessionFactory;
import org.hibernate.annotations.NaturalId;
import org.hibernate.annotations.SQLDelete;
import org.hibernate.annotations.SQLRestriction;
import org.hibernate.stat.Statistics;

import java.time.Instant;
import java.time.LocalDate;
import java.util.*;

public class WarehouseLab {

    public enum Category { FASTENER, STRUCTURAL, TOOLING }

    @Embeddable
    public record Money(long amountInCents, String currency) {}

    // ── step 1: products and stock ───────────────────────────────────────────
    @Entity(name = "Product")
    @Table(name = "product")
    @SQLDelete(sql = "update product set deleted = true where id = ?")   // step 6: soft delete
    @SQLRestriction("deleted = false")
    public static class Product {
        @Id @GeneratedValue(strategy = GenerationType.SEQUENCE)
        private Long id;
        @NaturalId
        @Column(nullable = false, unique = true, length = 16)
        private String sku;
        @Column(nullable = false)
        private String name;
        @Enumerated(EnumType.STRING)
        @Column(nullable = false, length = 16)
        private Category category;
        @Embedded
        private Money price;
        private boolean deleted;
        private Instant createdAt;
        private Instant updatedAt;
        private int revision;

        protected Product() {}
        Product(String sku, String name, Category category, long priceInCents) {
            this.sku = sku; this.name = name; this.category = category;
            this.price = new Money(priceInCents, "EUR");
        }
        @PrePersist void onCreate() { createdAt = updatedAt = Instant.now(); }
        @PreUpdate  void onUpdate() { updatedAt = Instant.now(); revision++; }

        Long id() { return id; }
        String sku() { return sku; }
        Category category() { return category; }
        Money price() { return price; }
        void rename(String n) { this.name = n; }
        boolean hasTimestamps() { return createdAt != null && updatedAt != null; }
        int revision() { return revision; }
        @Override public String toString() { return sku + " " + price.amountInCents() + "c"; }
    }

    @Entity(name = "StockLevel")
    @Table(name = "stock_level")
    public static class StockLevel {
        @Id
        private Long id;                                  // shares the product's id …
        @OneToOne(fetch = FetchType.LAZY) @MapsId          // … because this is the product's stock
        private Product product;
        private int onHand;
        @Version
        private int version;

        protected StockLevel() {}
        StockLevel(Product product, int onHand) { this.product = product; this.onHand = onHand; }
        int onHand() { return onHand; }
        int version() { return version; }
        void take(int qty) {
            if (qty > onHand) throw new IllegalStateException("only " + onHand + " on hand");
            onHand -= qty;
        }
    }

    // ── step 2: orders, lines, suppliers ────────────────────────────────────
    @Entity(name = "Order")
    @Table(name = "orders")                               // ORDER is a reserved word
    public static class Order {
        @Id @GeneratedValue(strategy = GenerationType.SEQUENCE)
        private Long id;
        private LocalDate placed;
        @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
        @OrderBy("id")
        private List lines = new ArrayList<>();

        protected Order() {}
        Order(LocalDate placed) { this.placed = placed; }
        Long id() { return id; }
        LocalDate placed() { return placed; }
        List lines() { return Collections.unmodifiableList(lines); }
        void addLine(Product p, int qty) {                // keeps both sides in step
            OrderLine l = new OrderLine(this, p, qty, p.price().amountInCents());
            lines.add(l);
        }
        void removeLine(OrderLine l) { lines.remove(l); l.order = null; }
        long totalInCents() { return lines.stream().mapToLong(OrderLine::subtotal).sum(); }
    }

    @Entity(name = "OrderLine")
    @Table(name = "order_line")
    public static class OrderLine {
        @Id @GeneratedValue(strategy = GenerationType.SEQUENCE)
        private Long id;
        @ManyToOne(fetch = FetchType.LAZY, optional = false)
        private Order order;
        @ManyToOne(fetch = FetchType.LAZY, optional = false)
        private Product product;
        private int qty;
        private long unitPriceInCents;                    // copied: a later price change must not rewrite history

        protected OrderLine() {}
        OrderLine(Order order, Product product, int qty, long unitPriceInCents) {
            this.order = order; this.product = product; this.qty = qty; this.unitPriceInCents = unitPriceInCents;
        }
        Product product() { return product; }
        int qty() { return qty; }
        long subtotal() { return qty * unitPriceInCents; }
    }

    @Entity(name = "Supplier")
    @Table(name = "supplier")
    public static class Supplier {
        @Id @GeneratedValue(strategy = GenerationType.SEQUENCE)
        private Long id;
        private String name;
        @ManyToMany
        @JoinTable(name = "supplier_product",
                   joinColumns = @JoinColumn(name = "supplier_id"),
                   inverseJoinColumns = @JoinColumn(name = "product_id"))
        private Set products = new HashSet<>();   // a Set: a List here makes every removal rewrite the join table

        protected Supplier() {}
        Supplier(String name) { this.name = name; }
        void supplies(Product p) { products.add(p); }
        Set products() { return products; }
    }

    // ── step 4: a projection that is not an entity ──────────────────────────
    public record CategoryRevenue(Category category, Long revenueInCents) {}

    // ── bootstrap ───────────────────────────────────────────────────────────
    static PersistenceConfiguration base(String schemaAction) {
        return new PersistenceConfiguration("warehouse")
            .managedClass(Product.class).managedClass(StockLevel.class)
            .managedClass(Order.class).managedClass(OrderLine.class).managedClass(Supplier.class)
            .property(PersistenceConfiguration.JDBC_URL, "jdbc:h2:mem:WarehouseLab;DB_CLOSE_DELAY=-1")
            .property(PersistenceConfiguration.JDBC_USER, "sa")
            .property(PersistenceConfiguration.JDBC_PASSWORD, "")
            .property(PersistenceConfiguration.SCHEMAGEN_DATABASE_ACTION, schemaAction)
            .property("hibernate.show_sql", "false")
            .property("hibernate.generate_statistics", "true");
    }

    static Product bySku(EntityManager em, String sku) {         // the natural key is how the business names a product
        return em.createQuery("select p from Product p where p.sku = :sku", Product.class)
                 .setParameter("sku", sku).getSingleResult();
    }

    static Statistics stats(EntityManagerFactory emf) {
        return emf.unwrap(SessionFactory.class).getStatistics();
    }

    // ── step 3: reserve stock ───────────────────────────────────────────────
    static void reservePessimistic(EntityManagerFactory emf, String sku, int qty) {
        try (EntityManager em = emf.createEntityManager()) {
            em.getTransaction().begin();
            Product p = bySku(em, sku);
            StockLevel s = em.find(StockLevel.class, p.id(), LockModeType.PESSIMISTIC_WRITE);  // select … for update
            s.take(qty);
            em.getTransaction().commit();
        }
    }

    static int reserveOptimistic(EntityManagerFactory emf, EntityManager stale, long productId, int qty) {
        // 'stale' already holds a StockLevel read before someone else changed it
        int attempts = 0;
        EntityManager em = stale;
        while (true) {
            attempts++;
            try {
                if (!em.getTransaction().isActive()) em.getTransaction().begin();
                StockLevel s = em.find(StockLevel.class, productId);
                s.take(qty);
                em.getTransaction().commit();
                em.close();
                return attempts;
            } catch (RollbackException e) {
                if (!(e.getCause() instanceof OptimisticLockException)) throw e;
                em.close();
                em = emf.createEntityManager();           // a fresh context: re-read, re-apply
            }
        }
    }

    public static void main(String[] args) {
        try (EntityManagerFactory emf = base("drop-and-create").createEntityManagerFactory()) {
            Statistics st = stats(emf);

            // ── seed ────────────────────────────────────────────────────────
            long boltId;
            try (EntityManager em = emf.createEntityManager()) {
                em.getTransaction().begin();
                Product bolt = new Product("BOLT-7", "M8 bolt", Category.FASTENER, 80);
                Product nut  = new Product("NUT-3", "M8 nut", Category.FASTENER, 25);
                Product gird = new Product("GIRD-1", "Steel girder", Category.STRUCTURAL, 120_000);
                Product cam  = new Product("CAM-9", "Cam follower", Category.TOOLING, 2_300);
                for (Product p : List.of(bolt, nut, gird, cam)) em.persist(p);
                em.persist(new StockLevel(bolt, 500));
                em.persist(new StockLevel(nut, 1_000));
                em.persist(new StockLevel(gird, 3));
                em.persist(new StockLevel(cam, 40));

                Supplier acme = new Supplier("Acme Fasteners");
                acme.supplies(bolt); acme.supplies(nut);
                em.persist(acme);

                Order o1 = new Order(LocalDate.of(2026, 10, 1));
                o1.addLine(bolt, 100); o1.addLine(nut, 100);
                Order o2 = new Order(LocalDate.of(2026, 10, 3));
                o2.addLine(gird, 1); o2.addLine(cam, 2);
                Order o3 = new Order(LocalDate.of(2026, 10, 9));
                o3.addLine(bolt, 20);
                for (Order o : List.of(o1, o2, o3)) em.persist(o);       // cascades to the lines
                em.getTransaction().commit();
                boltId = bolt.id();
            }
            System.out.println("-- step 1+2: mapped and seeded --");
            try (EntityManager em = emf.createEntityManager()) {
                Product bolt = em.find(Product.class, boltId);
                System.out.println("product     = " + bolt + " (" + bolt.category() + ")");
                System.out.println("stock id    = " + em.find(StockLevel.class, boltId).onHand() + " on hand, shares id " + boltId);
                Supplier s = em.createQuery("select s from Supplier s", Supplier.class).getSingleResult();
                System.out.println("supplier    = " + s.products().stream().map(Product::sku).sorted().toList());
                System.out.println("orders      = " + em.createQuery("select count(o) from Order o", Long.class).getSingleResult()
                    + ", lines = " + em.createQuery("select count(l) from OrderLine l", Long.class).getSingleResult());
            }

            // ── step 3 ──────────────────────────────────────────────────────
            System.out.println("-- step 3: reserving stock --");
            reservePessimistic(emf, "BOLT-7", 120);
            try (EntityManager em = emf.createEntityManager()) {
                System.out.println("after pessimistic reserve: " + em.find(StockLevel.class, boltId).onHand());
            }
            EntityManager stale = emf.createEntityManager();
            stale.getTransaction().begin();
            stale.find(StockLevel.class, boltId);                           // version 0 is now in this context
            reservePessimistic(emf, "BOLT-7", 30);                          // someone else commits first: version 1
            int attempts = reserveOptimistic(emf, stale, boltId, 50);
            try (EntityManager em = emf.createEntityManager()) {
                StockLevel s = em.find(StockLevel.class, boltId);
                System.out.println("optimistic reserve took " + attempts + " attempts; on hand " + s.onHand() + ", version " + s.version());
            }

            // ── step 4 ──────────────────────────────────────────────────────
            System.out.println("-- step 4: reports --");
            try (EntityManager em = emf.createEntityManager()) {
                List rev = em.createQuery(
                    "select new WarehouseLab$CategoryRevenue(p.category, sum(l.qty * l.unitPriceInCents)) " +
                    "from OrderLine l join l.product p group by p.category order by p.category", CategoryRevenue.class)
                    .getResultList();
                for (CategoryRevenue r : rev) System.out.println("revenue " + r.category() + " = " + r.revenueInCents());

                List top = em.createQuery(
                    "select p from Product p order by p.price.amountInCents desc, p.sku", Product.class)
                    .setFirstResult(0).setMaxResults(2).getResultList();
                System.out.println("top 2 by price = " + top);

                st.clear();
                List orders = em.createQuery(
                    "select distinct o from Order o join fetch o.lines l join fetch l.product order by o.placed", Order.class)
                    .getResultList();
                for (Order o : orders) {
                    System.out.println("order " + o.placed() + " total " + o.totalInCents() + "c, " + o.lines().size() + " lines, first " + o.lines().get(0).product().sku());
                }
                System.out.println("statements for " + orders.size() + " orders with lines and products: " + st.getPrepareStatementCount());
            }

            // ── step 6 (part a): callbacks ──────────────────────────────────
            System.out.println("-- step 6: callbacks and soft delete --");
            try (EntityManager em = emf.createEntityManager()) {
                em.getTransaction().begin();
                Product bolt = em.find(Product.class, boltId);
                System.out.println("timestamps set on persist: " + bolt.hasTimestamps() + ", revision " + bolt.revision());
                bolt.rename("M8 bolt, zinc");
                em.getTransaction().commit();
            }
            try (EntityManager em = emf.createEntityManager()) {
                em.getTransaction().begin();
                Product bolt = em.find(Product.class, boltId);
                System.out.println("revision after one update: " + bolt.revision());
                Product cam = bySku(em, "CAM-9");
                em.remove(cam);                                              // runs the @SQLDelete update instead
                em.getTransaction().commit();
            }
            try (EntityManager em = emf.createEntityManager()) {
                long visible = em.createQuery("select count(p) from Product p", Long.class).getSingleResult();
                Number rows = (Number) em.createNativeQuery("select count(*) from product").getSingleResult();
                System.out.println("products via JPQL: " + visible + ", rows in the table: " + rows);
            }
        }

        // ── step 5: bulk import on a second factory tuned for writes ────────
        System.out.println("-- step 5: bulk import --");
        try (EntityManagerFactory bulk = base("none")
                .property("hibernate.jdbc.batch_size", "50")
                .property("hibernate.order_inserts", "true")
                .createEntityManagerFactory()) {
            Statistics st = stats(bulk);
            st.clear();
            try (EntityManager em = bulk.createEntityManager()) {
                em.getTransaction().begin();
                for (int i = 1; i <= 500; i++) {
                    em.persist(new Product("IMP-" + i, "Imported part " + i, Category.TOOLING, 100 + i));
                    if (i % 50 == 0) { em.flush(); em.clear(); }           // keep the context small
                }
                em.getTransaction().commit();
            }
            System.out.println("entities inserted     : " + st.getEntityInsertCount());
            System.out.println("statements prepared   : " + st.getPrepareStatementCount());
            try (EntityManager em = bulk.createEntityManager()) {
                System.out.println("imported rows visible : " +
                    em.createQuery("select count(p) from Product p where p.sku like 'IMP-%'", Long.class).getSingleResult());
            }
        }
    }
}

Why each number is what it is. The stock row shares id 1 because @MapsId copied the bolt's generated key. After the pessimistic reserve of 120, 380 remain; the optimistic attempt read the row at version 0, another transaction took 30 and committed (version 1, 350 on hand), so the first commit was refused, the retry read 350 at version 1 and committed 300 at version 2 — the printed 3 is one more because the pessimistic path also bumps the version. Revenue sums qty × unitPriceInCents per line: 100 × 80 + 100 × 25 + 20 × 80 = 12100 for fasteners. The three orders with all their lines and products took 1 statement because of the two join fetches. Revision 1 after the rename shows @PreUpdate fired exactly once. JPQL sees 3 products after the soft delete; the native count sees the row still there, 4. And the import prepared 20 statements for 500 rows: ten batches of fifty inserts and ten sequence calls.

Extensions worth attempting
  • Turn show_sql back on and read the step 3 statements: find the for update, and the update … where id=? and version=?. Then change StockLevel to IDENTITY ids and watch the step 5 statement count explode.
  • Add a Warehouse entity and make StockLevel keyed by (product, warehouse) with an @EmbeddedId. What does reserve need to change, and which query in step 4 now has to say which warehouse it means?
  • Make the soft delete visible to one report: write a native query that lists deleted products, then a JPQL equivalent — and discover why the JPQL one cannot be written without @FilterDef/@Filter, which can be switched off per session where @SQLRestriction cannot.
