Where to go next

Further reading

Primary sources only — the specification, the Hibernate guide that documents the version this module runs, the tools, and the few books and articles that are worth the time. These are links, but nothing on this page loads them; the module remains fully offline.

Specifications and reference guides

  • Jakarta Persistence 3.2 Specification — the contract behind every annotation, the EntityManager lifecycle rules (chapter 3), the JPQL grammar (chapter 4), the Criteria API (chapter 6) and the exception hierarchy. Chapter 3's state transitions are §3 of this module, stated formally.
    https://jakarta.ee/specifications/persistence/3.2/
  • Hibernate ORM 7.4 documentation — the User Guide's chapters on the domain model (§2, §4, §8), the persistence context (§3), fetching (§5), HQL (§6), locking (§7), batching and caching (§9) and schema generation (§10). The HQL chapter documents the superset Hibernate accepts beyond JPQL.
    https://hibernate.org/orm/documentation/7.4/
  • Hibernate ORM migration guide — what changed between 6.x and 7.x: JPA 3.2, the PersistenceConfiguration bootstrap used in every program here, deprecated APIs such as byNaturalId, and changed defaults.
    https://github.com/hibernate/hibernate-orm/blob/main/migration-guide.adoc
  • H2 Database documentation — the SQL grammar and the jdbc:h2:mem: URL options (DB_CLOSE_DELAY=-1 keeps an in-memory database alive between connections) behind the verified programs.
    https://h2database.com/html/main.html
  • Flyway documentation and Liquibase documentation — versioned migrations, checksums, baselining an existing schema, and the naming conventions (V1__init.sql) that §10 recommends over hbm2ddl.auto=update.
    https://documentation.red-gate.com/flyway · https://docs.liquibase.com/

Articles that settle arguments

  • Vlad Mihalcea, "N+1 query problem with JPA and Hibernate" — the problem, how to detect it in tests by asserting on statement counts, and each fix measured (§5).
    https://vladmihalcea.com/n-plus-1-query-problem/
  • Vlad Mihalcea, "How to implement equals and hashCode using the JPA entity identifier" — the constant-hashCode idiom §11 uses, with the test that proves the id-based version breaks.
    https://vladmihalcea.com/how-to-implement-equals-and-hashcode-using-the-jpa-entity-identifier/
  • Vlad Mihalcea, "How to batch INSERT and UPDATE statements with Hibernate" — batch_size, ordered inserts, why IDENTITY defeats it, and how to verify with a proxy driver (§9).
    https://vladmihalcea.com/how-to-batch-insert-and-update-statements-with-hibernate/
  • Thorben Janssen's Hibernate tips — short, current answers to the questions that come up in code review: lazy one-to-one, @DynamicUpdate, entity graphs, natural ids.
    https://thorben-janssen.com/

Books

  • High-Performance Java Persistence, Vlad Mihalcea — the book behind §5, §7 and §9: how JDBC, the database and Hibernate interact, with measurements. Read it when you have shipped one Hibernate application and want to know why it behaves as it does.
  • Java Persistence with Spring Data and Hibernate, Cătălin Tudose — the long-form treatment of mapping, the persistence context, conversations and caching, and the bridge to Spring Data that this module deliberately left out.
  • Effective Java, Joshua Bloch, 3rd edition — items 10 and 11 are the equals/hashCode contract that §11 has to satisfy under the extra constraint of a generated id.

Tools worth knowing now

Tools for diagnosing a persistence layer
ToolUse it to
hibernate.generate_statistics + StatisticsCount prepared statements, entity loads, flushes and cache hits per unit of work; assert on them in tests so an N+1 regression fails the build.
datasource-proxyWrap the DataSource to log every statement with its bound parameters and batch sizes — what show_sql cannot show.
p6spyThe same at the JDBC-driver level, with timing per statement, for applications you cannot change.
EXPLAIN ANALYZETake the slowest statement from the log to the database and read the plan; a missing index is a database fix, not a Hibernate one.
TestcontainersRun the integration tests against the real database engine in a container, so that H2's dialect differences never reach production.
Schema export (schema-generation.scripts.action=create)Generate the DDL for the current mapping as the starting point of a migration script, as §10's worked example does.
jOOQThe type-safe SQL builder for the reports and bulk jobs that should not go through entities at all.
Where to go from here

This is the last module of the course. Three things will teach you more than any further reading.

  • Add Spring Data JPA on top, deliberately. A JpaRepository is an EntityManager with the boilerplate generated and @Transactional drawing the unit-of-work boundary for you. Every mechanism here — the context, flush timing, lazy loading, @Version — behaves identically underneath; the first thing to do in a new Spring Boot project is set spring.jpa.open-in-view=false and read the SQL.
  • Run the lab against PostgreSQL in Testcontainers. Watch which Hibernate: lines change (types, sequences, for update), move the generated DDL into a Flyway script, and start the application with validate. That is the production shape.
  • Finish the lab's extensions. The @EmbeddedId stock key, the filterable soft delete and the IDENTITY experiment each force a design decision this module only described — and the statistics will tell you whether you got it right.
